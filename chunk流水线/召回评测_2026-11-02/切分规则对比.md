# 切分规则对比：content_br（线上原版）与 md_struct / html_struct

三种方法都实现在 `recall_pipeline.py` 里，下面按代码的实际逻辑来讲。

## 一、content_br（线上基线）

实现在 `split()`，照搬线上规则，没有改动过。输入是 EC 的 `content` 字段，段落之间用 `<br>` 分隔。

1. **整篇够短就成一块**：去掉所有 `<br>` 后不超过 256 字，整篇作为一个 chunk。
2. **否则按 `<br>` 切成段，依次累加**：
   - 段与段之间直接拼接，不加任何分隔符，段落边界在 chunk 里看不出来。
   - 累加到超过 256 字时，把除最后一段以外的部分结算成一个 chunk。最后那段留到下一轮重新累加。
   - 如果某一段单独就超过 256 字，它会整段成为一个 chunk，不再往下切。**没有硬上限**，几千字的长段落也是一整块，送进向量模型时超出 512 token 的部分会被截断。
3. **文末剩余部分**单独成为最后一块。
4. **过滤**：丢掉长度小于 20 字的块。文末不足 20 字的尾巴也会被丢掉。

基线完全不认识结构：不知道哪里是标题、列表、表格，只能看到 `<br>`。表格切在哪一行，取决于字数累加到哪儿。

## 二、md_struct 和 html_struct 的共同框架

两者都分两步走：先把文档解析成一串"结构单元"，再用同一个切分函数 `chunk_struct()` 打包。两者唯一的区别在解析这一步。

### 结构单元有五种

- 标题：1–6 级，另外把"加粗的短行"当作第 7 级伪标题。
- 正文段落
- 列表项
- 表格行：每行转成 `单元格 | 单元格` 的形式，并记下所属表格的表头行。
- 代码块

### 打包规则

参数：软上限 256 字，硬上限 512 字，最短 20 字。

| 规则 | 说明 |
|---|---|
| 标题处断开 | 遇到标题先结算当前块。标题本身挂到下一段内容的开头，不会悬在块尾；连续几个标题会一起挂上去 |
| 同类才打包 | 正文段落和代码算一类，列表项算一类，表格按"同一张表"算一类。类别一变就断开，所以表格不会和正文混在一块 |
| 软上限 256 字 | 同类单元贪心打包，再加一个就超过 256 字时断开 |
| 不拆中等长段落 | 不超过 512 字的段落整段保留，哪怕它比 256 字长，也会独占一块 |
| 超长段落按句切 | 超过 512 字的段落按句末标点（。！？；… 和换行）切开，再打包到 256 字以内。单句超过 256 字时，先在逗号或顿号处切，找不到就硬切 |
| 表格每块带表头 | 一张表被切成多块时，每块开头都重复表头行，能识别出表头时才这样做 |
| 单元之间保留换行 | 块内各单元用换行连接，不像基线那样直接拼接 |
| 过滤 | 去掉换行后不足 20 字的块丢掉 |

几点补充：

- **实际块长会略超 512 字**。挂上去的标题和表头不计入"不拆"判断，所以块长可能是 512 字再加上标题或表头的长度。
- **没有加标题路径前缀**。带上下文前缀的版本（`_ctx`）目前不在评测范围内。
- **没有重叠**。相邻块之间不重复内容。

## 三、Markdown 解析规则

实现在 `parse_markdown()`，逐行扫描：

| 识别为 | 规则 |
|---|---|
| HTML 表格 | 以 `<table` 开头的行，一直读到 `</table>`。每行转成一个表格行单元。全是 `<th>` 的首行或 `<thead>` 里的行作为表头。单元格内的 `<br>` 变成空格 |
| 管道表格 | 以 `\|` 开头且下一行是 `\|---\|` 分隔线。第一行作为表头，单元格内的 `<br>` 变成换行 |
| 代码块 | ` ``` ` 包起来的部分 |
| 标题 | `#` 到 `######` |
| 伪标题 | 整行加粗、不超过 40 字、末尾没有标点 |
| 列表项 | 以 `-`、`*`、`+` 或 `1.`、`1)` 开头。嵌套列表被展平成同级列表项 |
| 正文段落 | 其余每个非空行各算一段 |

行内处理（`md_inline()`）：`<br>` 转成换行，图片只保留替代文字，链接只保留链接文字，去掉加粗标记和其他 HTML 标签，合并多余空白。

**已知局限：**

- 结构完全靠真实换行识别。如果 EC 用 `<br>` 代替换行，`<br>` 后面的 `##`、`-` 都识别不出来，整行会变成一个标题或一个段落。
- 不识别用 `===`、`---` 下划线写的标题，也不处理引用标记 `>`。

## 四、HTML 解析规则

实现在 `parse_html()`，按 DOM 树遍历：

| 识别为 | 规则 |
|---|---|
| 跳过 | script、style、noscript、template、svg、iframe、head、title、meta、link |
| 标题 | `h1`–`h6` |
| 伪标题 | `<p>` 里只有一个 `<strong>` 或 `<b>`，且是短行 |
| 正文段落 | `<p>` |
| 列表项 | `ul`、`ol` 的每个直接子 `li`。嵌套列表递归展开 |
| 表格 | `<table>`，规则同 Markdown 的 HTML 表格。嵌套表格的文字算在外层单元格里 |
| 代码块 | `<pre>` |
| 行内文字 | span、a、strong、em、font 等行内标签和裸文字，累积起来拼成一段 |
| 段落边界 | div、section、blockquote 等其他容器，进入和离开时各断一次段 |

所有 `<br>` 先统一换成换行。

**已知局限：**

- html 为空的网页切不出任何块。全库约 21% 的网页是这种情况，评测里 html_struct 吃亏主要就是因为这个。
- `li` 里嵌套的表格会被跳过，这部分内容会丢失。这种情况不多见。

## 一句话对比

| | content_br | md_struct / html_struct |
|---|---|---|
| 切分依据 | 只看 `<br>` | 标题、列表、表格、段落 |
| 块长 | ≤256 字，但单个长段落不切、没有上限 | 软上限 256 字，中等段落最长约 512 字 |
| 表格 | 按字数切，可能切在任意位置 | 按行切，每块都带表头 |
| 标题 | 可能和下一节内容分在不同块 | 一定和下一段内容在同一块 |
| 段落边界 | 直接拼接，块内看不出边界 | 保留换行 |
