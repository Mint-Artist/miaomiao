# EC Markdown 切分（结构保护优先 + 256 字符）

把上游 EC 输出的 Markdown 正文切成纯文本 chunk。只依赖 Python 标准库（3.8+）。

## 用法

```bash
python3 md_chunker.py --input in.jsonl --output out.jsonl
```

- 输入每行一个 JSON 对象，`markdown` 键是正文；输出原样保留所有字段，新增 `chunks`（字符串列表）。
- `markdown` 缺失或为空时，`chunks` 为 `[]`。单条解析出错时退化为纯文本拆分，并在 stderr 报出行号，不中断整批。
- 运行结束在 stderr 打印汇总：条数、块数、长度 P50/P90/最大、超过 256 的比例。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--markdown-key` | `markdown` | 正文所在的键 |
| `--chunks-key` | `chunks` | 新增的键名 |
| `--target` | 256 | 软目标：贪心装箱到这个长度 |
| `--hard` | 512 | 硬上限：单个结构单元不超过它就不拆；任何块都不超过它 |
| `--heading-context` | 关 | 每块前补上所在章节的祖先标题路径（计入长度，最多 100 字） |
| `--keep-image-alt` | 关 | 图片保留说明文字（默认整张图片去掉） |

也可以在代码里调用：

```python
from md_chunker import chunk_markdown
chunks = chunk_markdown(markdown_text)            # -> list[str]
```

## 输入格式约定

- 正文是 Markdown：`#` 标题（也支持 `===` / `---` 下划线式标题）、段落（空行分隔）、列表、引用、代码块。
- 表格是 HTML `<table>`（可跨多行，可含 `rowspan` / `colspan`、`thead`、`caption`）；也兼容 Markdown 管道表。
- 链接 `[文字](地址)`、`[文字][引用]`、`<https://…>`、图片 `![说明](地址)` 都会被清理。

## 切分规则

1. **清洗成纯文本**
   - 链接只保留文字，地址去掉；链接地址里带括号（如 `Python_(语言)`）也能正确识别。
   - 图片整体去掉，包括 `[![图](a.png)](链接)` 这种图片链接。
   - 去掉 `**` `~~` `*` `` ` `` 等标记和行内 HTML 标签，`<br>` 变成换行，HTML 实体还原。
   - `\*`、`\[` 这类转义保留为字面字符；`3*4*5` 不当作强调；全角括号和 `[1]` 这类普通方括号原样保留；正文里直接写出的网址保留。
2. **结构单元不拆**：段落、列表项、引用段、代码块各是一个单元。
   - 单元连同绑定的标题不超过 512 字就整体保留，可以超过 256。
   - 超过 512 才拆成不超过 256 的片段，切点优先级：换行或句末（`。！？；`）→ 逗号、顿号、冒号 → 硬切。
3. **标题绑定**：标题（包括连续的多级标题）并入后面第一个单元，标题不会单独成块。表格前的标题并入表格的第一块。
4. **引导句绑定**：以"："结尾的段落和下一个单元（列表、表格）合在一起，合并后不超过 512。
5. **贪心装箱**：
   - 同一小节内的文本单元依次合并，合并后不超过 256。
   - 当前块已经超过 256 时，不再往里放。
   - 遇到新标题或者换了小节，就开新块，不跨章节。
6. **表格**：
   - 合并单元格展开成网格：`rowspan` 的值复制到它覆盖的每一行；`colspan` 只保留一次，不重复。
   - 每行一行文字，单元格之间用 ` | ` 分隔。
   - 表头是 `thead` 或开头全是 `th` 的行，都没有就取第一行。
   - 按行装箱到 256，续块开头重复表头（表头超过 128 字时不重复）。单行不超过 512 时整行不拆。
   - 表格不和普通正文合在一块（引导句除外）。
   - 只有一列的表格多为排版用途，按普通段落处理。
7. **兜底**：任何块都不超过 512 字。

### 示例

```markdown
## 三、主要城市预报

<table>
<thead><tr><th>城市</th><th>最低气温</th><th>风力</th></tr></thead>
<tr><td rowspan="2">河北</td><td>石家庄 -3℃</td><td>4级</td></tr>
<tr><td>张家口 -9℃</td><td>6级</td></tr>
<tr><td colspan="2">北京 -2℃</td><td>3级</td></tr>
</table>
```

切出一块：

```
三、主要城市预报
城市 | 最低气温 | 风力
河北 | 石家庄 -3℃ | 4级
河北 | 张家口 -9℃ | 6级
北京 -2℃ | 3级
```

更多样例见 `samples/sample.jsonl`（输入）和 `samples/sample.chunked.jsonl`（输出）。

## 验证

```bash
python3 -m unittest -v test_md_chunker    # 21 个用例
```

另外用之前开源框架对照实验的 209 个网页（简版 HTML，本地数据，未纳入仓库）做了压力测试。
先把它们转成和 EC 相同格式的 Markdown（正文 Markdown、链接 `[]()`、表格保留 HTML），再全部切分：

| | 块/页 | 长度 P50 | P90 | 最大 | >256% |
|---|---:|---:|---:|---:|---:|
| 本切分器 | 7.3 | 207 | 253 | 512 | 6.9 |
| 本切分器 + `--heading-context` | 8.0 | 210 | 254 | 501 | 8.3 |
| 参照：自研 structure_protect（简版 HTML 输入） | 7.7 | 191 | 254 | 511 | 7.7 |

- 没有解析失败，209 页耗时约 0.2 秒。
- 没有残留 `[]()`、`![]()` 语法。少数块里有网址，都是原文直接写出的网址，不是链接语法。
- 和规范化正文对比，8 字片段覆盖率平均 0.998。低于 1 的部分是 `- ` 列表符号和 `----` 分隔线被去掉，没有丢正文。

这批 Markdown 是由简版 HTML 转出来的，不是 EC 的真实输出。拿到真实数据后，建议先抽样核对标题层级、段落空行和表格这几处。

## 已知限制

- 只认 Markdown 和 HTML 的显式结构。原文里没有标记的标题（普通段落写的"一、""（二）"）不会当作标题。
- 链接文字一律保留，"分享到微博""返回顶部"这类导航文字如果 EC 没去掉，会留在正文里。
- 长度按 Unicode 字符计，不是 embedding 模型的 token 数。
- 单个单元格本身超过 512 字时，会按句子拆开，拆开后的片段只带表头，不带同行其他单元格。
