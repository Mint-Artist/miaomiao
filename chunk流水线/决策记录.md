## 2026-09-24 本地流水线 v0.2.0【已实施】

- **固定输入不变**：简版 HTML 仍是上游契约。统一解析派生 T、DOM 元素范围、表格行列/跨度、
  资源位置及结构原子；T 与前三个规格文本逐字一致（包括空白）。
- **正文交付与检索分开**：`chunks.jsonl` 的 `text` 按序严格拼回 T；
  `retrieval.jsonl` 使用 `index_text`，当前一对一映射，并明确禁止用于正文拼接。
  保留来源范围，为以后额外的重叠/层级索引留出边界。
- **五套可运行配置**：递归硬预算、结构硬预算、结构类型保护，以及两种结构策略各自加结构上下文。
  公共解析/序列化/验收共享，不复制每实验一套项目。
- **目标与上限**：保护策略必须显式传 H，未设置即报错。本次样例 H=512 仅是实验参数；
  表格仍受 256 目标约束；超目标原因与降级原因分别记账。
- **上下文与资源**：标题按源范围去重；可选标题过长逐级裁剪并记录；
  表格补表头/片段行列信息及跨行继承值。图片 alt/URL 留在侧表，不注入原文。
- **已有 LLM 能力的接入适配**：输出请求清单并读取带模型/prompt/正文版本的缓存，
  冻结边界后生成检索视图。没有调用真实模型；缺失、过期和超限明确失败。
- **真实 token 守卫接口**：须提供实际 tokenizer 回调及标识；没有它时报告明确未验证 token 上限。
  不提供无效的 semantic/late-chunking/训练模型开关。
- **旧版冻结**：[31 文件哈希与依赖清单](baselines/legacy_manifest.json)，旧实现及产物保持原样。
  这不是生产 B0。新实验另记录实现哈希、配置、正文和输出哈希。
- **本地验收**：41 个测试方法（包括三个样本×五配置及固定种子随机检查）；旧版 37/37、36/36。
  [结果比较](output/vnext_local_h512/comparison.md)：所有 15 个组合均严格还原且无绝对超限。
  律图结构上下文硬预算为 7 块/拆 1 原子，类型保护为 6 块/拆 0 原子，最大 262 字符。
  这些不是搜索效果指标，不据此选生产赢家。
- **显式限制**：嵌套表格、`rowspan=0` 等尚未支持并拒绝处理；复杂表格/超长内容目前主要通过合成案例，
  需补真实验收。语义切分、父子返回、Late Chunking、多格式表格索引、真实搜索评测均未实施。

## 总体架构（2026-09-23 确认）【已实施】

两段式：**建库前固定的结构提取 → 下游可动态迭代的切分策略**。
与 Google Cloud（layout parser→chunking config）、Azure（Layout→Markdown→Split）、
Unstructured（partition→chunk）、Docling（文档模型→HybridChunker）分层同构，
证据见 `../调研与资料/chunk_research_2026-09-20/html_structure_research/HTML结构切分_业界调研.md`。
中间产物是**受控标签的简版 HTML 字符串**，对应 EC 需求契约
（`../调研与资料/EC网页正文标签保留需求_简版.md`）。

## 阶段一：原始 HTML → 简版 HTML（2026-09-23 实施，验收 37/37）【已实施】

- 标签白名单（h1-h6/p/br/ul/ol/li/table 全家/figure/blockquote/pre/code/a/img/strong/em）；
  属性白名单（a[href]、img[src/alt]、ol[start]、li[value]、td/th[rowspan/colspan/scope/headers]）；
  id/style/on* 一律删除。
- **保留 strong/em**（有意偏离 EC 文档）：伪标题线索，删了不可逆。
- **标题级别按原文保留，不新增原文不存在的标题**；伪标题默认不提升，
  可选 `--promote-pseudo-headings`（标 `data-origin="inferred"` 区分原生与推断）。
- 表格重建 thead/tbody（修正原始 HTML 错乱嵌套）；单元格内 `<br>` 保留为格内换行。
- 去噪三层：站点 `strip` 选择器（样板块整块移除）→ DROP_TAGS → 噪声词元
  （ad/promo/recommend/share/ymzy…；有误伤风险，新站点必看报告的 `dropped:*`）。
- 元信息经 `metadata` 选择器提为 `div.metadata`（不进正文流，作上下文来源）。
- 可选 `--anchors` 给块级元素加 `data-src` 锚点（评估回溯/父子扩展用，正式交付不含）。
- 提取器版本化（`EXTRACTOR_VERSION`），report.json 记录命中配置、标签统计、告警。
- 站点配置：huawei_support / gk100 / lvtu_zs / generic 兜底；新站点加配置不改管线。
- 2026-09-23 两条 URL 线上实抓验证：与本地快照提取结果逐字一致。

## 阶段二：简版 HTML → chunk（2026-09-23 与需求方逐条确认，验收 36/36）【已实施】

1. **预算**：256 Unicode 字符，含注入上下文，不含图片 URL；预留 token 计数接口。
2. **预算与完整性冲突：预算硬上限优先，按类型降级**——否决 LangChain 式整表保护。
   降级链：表格按连续行分组+重复表头；列表项拆子段落；段落按 句号→分号→逗号/顿号→
   硬断；续块带 `continued` + `parent_id` + 完整上下文，`split_reason` 记账不静默。
3. **上下文注入 `contextual_text` 且计入预算**：文档标题 + 祖先标题路径（只带祖先链，
   占预算超 40% 逐级丢深层）+ 表头（含表格行的块）；`text` 保持纯原文。
   metadata 注入默认关（华为适用清单 90+ 字，实测注入后 3 块变 8 块、须知与步骤被拆散）。
   LLM 上下文留 `llm_context` 接口默认不接——收益需实验验证（NAACL 2025 P01：不稳定），
   接入时按 chunk 哈希缓存、prompt 版本化。
4. **短章节不跨主题合并**（默认关，实验开关）；**伪标题前断块**（默认开，
   解决"一、二、三、"粘在前块尾的问题）。
5. 输出 JSONL schema：chunk_id / doc_id / url / text / contextual_text / chars /
   contextual_chars / context_sources / heading_path / parent_id / continued /
   prev / next / data_src / kind / split_reason / cross_section / images / atom_ids /
   chunker_version / config_hash。

## 2026-09-24 需求确认【本地首版已实施；生产参数待定】

1. **正文还原**：以固定、独立于切分策略的规范化正文 T 为基准，
   `''.join(chunk.text for chunk in chunks) == T`，包含空白严格相等。
   标题、metadata、表头全部保留；不再使用旧验收的排除清单。
   重复注入的标题、表头及 LLM 生成内容只进入 `contextual_text`。
2. **内容保留不等于独立成块**：标题可与所属正文同块，优先随下文；
   metadata 是否独立成块以及如何参与检索留作实验。
   此项明确取代早先“metadata 已定为单独成块参与检索”的表述。
3. **目标预算与类型保护**：初始目标 256 Unicode 字符，含上下文、不含图片 URL；
   段落、列表项、提示框允许独立超目标；表格按连续行分组，超长行再降级。
   绝对上限另定，512 不是已确认值；当前硬上限实现保留作对照。
   标题/metadata 分组、绝对上限和上下文裁剪的具体组合仍需按规格落地验收。
