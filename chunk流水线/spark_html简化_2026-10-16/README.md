# HtmlSimplify：原始网页 HTML → 简版 HTML（单个 Scala 文件，Spark）

交付物只有一个文件：[HtmlSimplify.scala](HtmlSimplify.scala)。依赖只有 **jsoup 1.23.2**，Spark 由集群提供。JSON 处理用 Spark 自带的 Jackson。
- 打出来的 jar 约 600KB，里面只有 jsoup 和本程序；
- 本地验证用的是 Spark 3.5.9 / Scala 2.12 / JDK 17；
- 集群如果是 Scala 2.13 的 Spark，只需把文件第一行改成 `//> using scala 2.13.x`。

## 用法

```bash
# 1. 本地试跑：不需要集群，JSONL 进、JSONL 出（每行 {"url": ..., "pg": 原始HTML}）
scala-cli run HtmlSimplify.scala -- --local --input pages.jsonl --output out.jsonl

# 2. 打包：Spark 不打进包里
scala-cli --power package HtmlSimplify.scala --assembly --preamble=false \
  --provided org.apache.spark::spark-sql -o html-simplify.jar

# 3. 集群
spark-submit --class HtmlSimplify html-simplify.jar \
  --input hdfs:///path/in --output hdfs:///path/out \
  [--input-format json|parquet|orc] [--url-col url] [--html-col pg] [--partitions 2000] \
  [--output-format parquet|json] [--mode overwrite] [--with-text] [--no-plain-headings] \
  [--site-rules hdfs:///conf/site_rules.json]
```

**同事那边不想装 scala-cli 时**：把文件里的 `//> using` 几行换成 sbt / maven 依赖即可。只需要两个：`org.jsoup:jsoup:1.23.2`，以及 scope 为 provided 的 `spark-sql`。代码本身不依赖任何构建工具。

**调试某几页为什么抽成这样**（本地模式）：加 `--explain id1,id2`（JSONL 里要有 `id` 字段），会打印候选容器的得分和最终选中的节点。

### 输入

| 项目 | 说明 |
|---|---|
| 字段 | 默认读 `url` 和 `pg` 两列，可以用参数改列名 |
| pg 的格式 | 应是已解码的 HTML 字符串；多套了一层或两层 JSON 字符串时会自动解开 |
| 原始字节 | HDFS 上如果是原始字节而不是字符串，需要先在读取时解码 |

### 输出

每页一行，字段如下：

| 字段 | 说明 |
|---|---|
| `html` | 简版 HTML。块级元素一行一个，第一块是 `<h1>标题</h1>` |
| `text` | 纯文本，需要 `--with-text` 才输出（本地模式总是输出） |
| `title` | 页面标题 |
| `status` | `ok` / `empty`（没有正文文字）/ `too_large`（超过 500 万字符）/ `error` |
| `error` | 出错时的信息 |
| `locate` | 正文定位方式：`site` 站点规则 / `score` 打分 / `body` 找不到正文、退回整页 |
| `headings` / `inferredHeadings` / `tables` / `lists` / `images` / `textChars` | 结构计数，便于抽查 |
| `inputChars` / `millis` / `version` | 输入长度、耗时、程序版本 |

建议上线后定期抽查 `locate=body`、`status=empty`、`textChars` 很小的页面。

**简版 HTML 只用这些标签**：h1–h6、p、br、ul/ol/li、table/caption/thead/tbody/tr/th/td、pre、blockquote、a[href]、img[src,alt]、strong、em、code。

**推断出的标题**：原文没有用 h 标签、而是从加粗、字号、class 名或中文编号推断出来的小标题，输出为 `<hN data-origin="inferred">`。下游可以选择用，也可以当作普通段落。`--no-plain-headings` 用来关闭"无任何标记的短行"这一条推断规则。

### 站点规则（可选）

```json
{"example.com": {"content": ["div.article-body"], "remove": [".share-bar"]}}
```

- 按域名后缀匹配；
- `content` 里所有选择器命中的元素，按文档顺序合起来作为正文；
- `remove` 里的元素会先被删掉。

代码里内置了百度知道、搜狗问问两条规则。外部规则文件里同名的条目会覆盖内置规则。

## 怎么做的

1. **解码与防护**：解开多套的 JSON 字符串；超过 500 万字符的页面直接标记 too_large；每条记录单独捕获异常，单页出错不影响整批。
2. **解析**：用 jsoup，按 HTML5 规范容错。2 万层嵌套的页面也不会栈溢出，超过 300 层的部分直接取文字。
3. **去掉不可能是正文的节点**：脚本、样式、iframe、表单控件、nav / aside / footer、注释、行内样式声明为隐藏的短元素。**不删除 `<form>`**，因为很多 .aspx 政府站把整页包在一个 form 里。
4. **定位正文：子树净得分**：
   - 每个文本块单独打分。像正文的（有中文标点、链接少）给正分；像样板的（导航、链接、链接包着的广告卡片、无标点短行）给负分。表格单元格和代码块按字数给正分，不要求有标点。
   - 每个节点的得分 = 它子树里所有文本块的分数之和，取得分最高的节点作为正文容器。这样内容分散在多层嵌套里也能汇总到共同祖先，噪声多的祖先会自然落选。
   - 再在向上 2 层范围内，合并得分够高、链接少的旁支，例如被拆成几块的正文、多个回答。
5. **按白名单重建一棵新树**（不在原树上删改）：
   - div 等容器拆壳，但当作段落边界；
   - 连续两个 `<br>`，或"`<br>` + 全角缩进"，切分为新段落；
   - 布局用的表格拆成段落；数据表格规整为 thead / tbody，保留 rowspan / colspan；
   - 链接密集的区块、class/id 命中噪声词的区块整块丢弃；
   - 懒加载图片取 data-original / data-src，链接和图片地址都转成绝对地址。
6. **去样板**：
   - 界面按钮文字（"大字体""展开全部""提交"等）；
   - 150 字以内的版权、平台声明；
   - 正文后半段出现"相关阅读""猜你喜欢"等分隔行时，从那里截断；
   - 首尾的面包屑、"上一篇""责任编辑"，以及末尾整段都是链接的块。
7. **推断小标题**：对象是短行（≤40 字、不以句末标点结尾、不以日期开头、不是"来源 / 作者"一类元信息），满足其一即提升：
   - **加粗、字号或 class 信号**：整段加粗、字号明显大于本页正文主体字号、或 class 含 title 等标题词。某种信号覆盖全页一半以上时停用该信号。连续 1–3 行这样的短行后面跟着正文时，整组都提升。
   - **中文编号**：以"一、""（一）""1.""（1）"开头，下一块是正文，而不是同级的编号短行。
   - **无标记短行**：≤20 字、不含逗号句号冒号等，夹在两段正文之间，后一段 ≥60 字。
   - **层级**：编号式按"一、→ h2，（一）→ h3，1. → h4，（1）→ h5"。无编号的，页面上有"一、"级标题时为 h3，否则为 h2。
8. **输出**：确定性序列化，同一输入永远得到同一输出。

## 验证（`validation/`）

**数据**：之前开源对照用过的 235 个真实中文网页（HTTP 200）。对照是现有链路（Trafilatura 定位 + 自研简化）在其中 209 页上的输出。

| 项目 | 结果 |
|---|---|
| 正文一致性（209 页，8 字片段互相覆盖，按字数加权） | 对现有链路正文的召回 0.941，精确 0.952，总字数 1.00 倍。差异大的页面逐页看过，大多是现有链路抽进了噪声：JS 提示、导航、推荐列表、举报表单、社交账号链接 |
| 现有链路没有产出的 26 页 | 新实现 16 页为空（多为需要 JS 渲染的页面），10 页有正文 |
| 合成问题的证据句保留（430 条） | 410 条，95.3%。没找到的 20 条中，12 条本身就是噪声（JS 提示、导航、热线、相关推荐链接）；只算真正的正文证据是 **410/418 = 98.1%**。真实漏抽集中在 5 页：彩票页的另一张表、快乐 8 开奖号码、买购网一个列表、视频页的来源行、新浪一页的标题 |
| 标题召回（944 个参照正文标题） | **49.6%**，现有链路 35.9% |
| 推断标题准确率 | 按参照标注判，可判定部分为 92%（392 对 / 34 错）。人工复看"错"的部分，约一半其实是标题（参照标注漏标），实际约 96%。真错的主要是淘口令、京东口令这类促销行，以及个别列表项 |
| 表格行 / 列表项 | 表格行 125 / 125。列表项 145 / 186，少掉的都是现有链路里的推荐新闻、日期列表、社交账号链接 |
| 边界情况（`edge.jsonl`，16 例） | 空输入、缺字段、纯文本、超大页面、2 万层嵌套、损坏的 HTML、套两层 JSON、懒加载图片、`<br>` 加全角缩进分段、rowspan、嵌套列表、嵌套表格、隐藏元素、.aspx 的 form、frameset、只有脚本、非法 URL、`<pre>`，全部按预期处理 |
| Spark 路径 | 进程内 `local[2]` 跑完整作业，235 条输出与本地模式逐字段一致；只用打出来的 jar 加 Spark 依赖、在 JDK 17 上跑通，输出 Parquet |
| 速度 | 单线程平均 4.5 毫秒/页（M 系列 CPU），约 200 页/秒/核 |

### 下游检索（`retrieval_eval.py`）

做法：两边的输出走同一套切分（chunk_pipeline），用同样的 430 道题、bge-m3 全库检索，逐题配对比较。

| 切分配置 | 全部 430 题 ΔMRR | 两边都能找到证据的 410 题 ΔMRR |
|---|---|---|
| 结构类型保护 + 上下文（线上配置） | −4.6 [−7.1, −2.1] | **−1.3 [−3.2, +0.8]，不显著** |
| 结构类型保护 | −5.7 [−8.2, −3.3] | −2.5 [−4.5, −0.5] |

ΔMRR 为新实现减现有链路，×100，括号内为 95% 区间。

**全量的差距主要来自"证据找不到"**：
- 这 20 题直接记 0 分，其中 12 题的证据本身就是噪声；
- 这些题是从现有链路的输出里出的，对抽取更干净的一方天然不利。

**不带上下文时可比题上仍差 2.5，原因是推断标题让章节变多**：
- 新实现识别出更多小标题，切分器把每个标题当作章节的硬边界，块变多变小；
- 例如一页从 13 块变成 19 块，块变小会拉低 MRR；
- 把推断标题还原成普通段落后，"加上下文"配置在可比题上为 −0.2 [−2.1, +1.7]。

如果要和"更准的标题"配合得更好，应该在切分侧把同一父标题下过短的相邻小节合并到软目标。这是切分器的改动，不在本程序范围内。

## 已知局限

- **需要 JS 渲染的页面**（百度教育、网易手机版文章、Vue 模板页等）：原始 HTML 里本来就没有正文，输出为空或只有标题。要处理只能在抓取侧渲染。
- **数字为主的展示型页面**（彩票开奖页）：页面上有多张表、用 flex 布局拼出来的号码，只能抽到其中一部分。
- **CSS 文件里定义的样式拿不到**：字号、加粗等信号只能读行内 style 和标签。写在外部 CSS 里的样式需要渲染才能获得。
- **问答类站点**：多个回答分散在多层嵌套里时，通用打分可能只取到一个回答。已内置百度知道、搜狗问问的规则；其他大站建议按需补充站点规则。

## 复现验证

仓库里只有代码和报告，**不包含验证数据**：
- 不包含 `input.jsonl`（235 个第三方网站的原始网页）、各 `out_*.jsonl` 输出、`compare_viewer.html` 对比页，以及打包出的 jar；
- 验证脚本依赖本地的实验目录 `开源对照_2026-09-28`（原始网页与现有链路输出）、`语义切分_2026-09-29`（合成问题与检索评测）、`简版HTML结构审计_2026-10-16`（参照标题）。

下面的命令需要在有这些目录的本地工作区里运行。

```bash
cd validation
scala-cli run ../HtmlSimplify.scala -- --local --input input.jsonl --output out_final.jsonl
../../开源对照_2026-09-28/.venv/bin/python compare.py out_final.jsonl            # 正文 / 证据 / 标题 / 结构对比
../../语义切分_2026-09-29/.venv/bin/python retrieval_eval.py out_final.jsonl      # 下游检索（bge-m3 走硅基流动 API，有缓存）
python3 make_viewer.py out_final.jsonl                                            # compare_viewer.html：逐页并排查看
```

`input.jsonl` 由 `../开源对照_2026-09-28/data/raw` 生成，其中每 7 条有 1 条的 pg 被多套了一层 JSON，用来测试解码。边界情况：`python3 gen_edge.py` 生成 `edge.jsonl` 后同样用 `--local` 跑。
