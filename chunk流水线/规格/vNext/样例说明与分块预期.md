# vNext 样例说明与分块预期

本文件与 [正文契约与切分规则](正文契约与切分规则.md) 配套。以下分块是行为预期，不是新切分器的执行结果；尚未指定 H，也没有选定 metadata 分组实验配置。

三个 `.normalized.txt` 是完整的规范化正文参照。SHA-256、来源路径、字符数和核对结果见 [样例核对.json](样例/样例核对.json)。文本采用 UTF-8、LF，每个文件以 LF 结束。高考文本内 TAB 分隔单元格，单元格内 `<br>` 也以 LF 保留，因此文本行数不是表格行数。

## 1. 华为：metadata 不消失，标题合块不改变顺序

- [原简版 HTML](../../html结构切分_2026-09-23/output/huawei_zh-cn16079039.simplified.html)
- [完整规范化正文](样例/huawei_zh-cn16079039.normalized.txt)

正文开头为：

```text
华为儿童手表跨品牌添加联系人
适用产品：华为超新星手表 X1，华为儿童手表 5，华为儿童手表 5 Pro 感光炫彩版，华为超新星手表 X1 Pro，华为儿童手表 5X Pro，华为儿童手表 5 新耀版，华为儿童手表 5X，华为儿童手表 5 活力版，华为儿童手表 5 Pro
适用版本：不涉及系统版本
通过与其他品牌手表面对面摇一摇，即可轻松添加联系人，实现语音通话。
```

源顺序是 `标题 e1 → metadata e2（e3/e4）→ 介绍 e5/e6 → 提示框 e7 → 步骤 e12/e15/e17`。

预期分组：

| 区域 | 预期 |
|---|---|
| 文档开头 | 标题可与邻接 metadata/介绍在预算内合块；不得跳过 metadata 直接拼标题和介绍 |
| metadata 独立实验 | metadata 仍占原来的正文范围；如因此标题单独成块，明确报告绑定例外，不把标题挪到后面 |
| 功能介绍 | 两个完整段落按预算装箱；不以延续旧版“三块”为目标 |
| 须知提示框 | 四条须知构成一个保护单元，保留条目换行；只超 256 时独立成块，超过 H 才降级 |
| 三步流程 | 每个 li 是保护单元，步骤内型号分支留在该 li；三个 li 能一起满足目标时可合块，否则在步骤之间拆 |

资源：四张图片和正文链接继续有来源映射，不把 URL 写入 `text`。图片缺 alt 的位置不生成说明文字。

旧版去空白覆盖仅比较 515 字；完整简版 HTML 有 646 个非空白字符。差异来自旧验收排除的标题和 metadata，不是本规范新增了 131 字生成内容。

## 2. 高考：章节随下文、表头原文一次、检索副本可重复

- [原简版 HTML](../../html结构切分_2026-09-23/output/gk100_read_27177662.simplified.html)
- [完整规范化正文](样例/gk100_read_27177662.normalized.txt)

一个应优先同块的连续源片段：

```text
一、安徽2026高考一分一段表
2026年安徽高考成绩排名表将于6月25日公布，届时本文同步教育考试院整理更新，可保持关注了解。下面参考安徽2025年高考一分一段表，介绍分数排名情况：
```

对应 `e8` 标题与 `e9` 首段。其后的 `1、物理类` 和 `2、历史类` 是原文加粗伪标题，也应优先随各自下文，不能落在上一块尾部。

表格开头的精确规范化字符串用转义表示为：

```json
"学校名\t专业组\t2025\n分数\t2025\n位次\n清华大学\t004组\t688\t85\n上海交通大学\t003组\t687\t94\n"
```

表头的两处内部换行来自原文 `<br>`，不能当作三行表头。连续数据行的分组由 DOM 行范围决定。

预期分组：

| 区域 | `text` | `contextual_text` 的增补 |
|---|---|---|
| 章节一 | 标题和章节首段依次保留，优先同块 | 需要时补文档标题，不重复已在正文里的同源标题 |
| 物理/历史两个子节 | 各伪标题与下文绑定，段落完整性优先 | 标题路径按预算补充 |
| 章节二介绍 | 保留章节标题与“篇幅有限…”段落 | 需要时补文档标题 |
| 第一组表格行 | 原始表头优先与首行同块，再装箱后续完整行 | 表头已在块内时不重复注入同源表头 |
| 后续表格组 | 只有对应连续数据行的原始切片 | 补标题路径与表头，全部计入预算 |

`text` 全量拼接后，表头出现一次，171 行数据依次出现，首行为清华大学/004组/688/85，末行为苏州大学/005组/631/9977。不能为了给续行补列信息而把其他列的正文反复复制进 `text`。

旧版覆盖口径为 3726 个非空白字符，完整简版 HTML 为 3822 个；新版规范化文本共 4561 字符，其中包括保留的空白及明确生成的结构分隔符。字符预算口径变化也需要记录，不能仅比较旧、新块数。

## 3. 律图：伪标题随下文，长段落不因目标值而被强拆

- [原简版 HTML](../../html结构切分_2026-09-23/output/lvtu_8655766.simplified.html)
- [完整规范化正文](样例/lvtu_8655766.normalized.txt)

明确的标题与正文同块示例（末尾包含 LF）：

```json
"一、公司裁员提成部分能要回吗\n公司裁员时提成部分能否要回，需看具体情况。\n"
```

对应 `e7/e8`，是原规范化正文里的连续切片；无需把标题单独输出后再借上下文补到下一块。

预期分组：

- 文档标题、来源、日期和阅读量保留在开头，不从还原流消失。
- 三个加粗伪标题仍是源段落，不改写为新标题文字；作为分块关联信号，各自优先跟随后文。
- “若劳动合同、公司规章制度明确约定…”等段落优先完整。同章多个段落合计超目标时，在段落之间断开。
- 若某个完整段落含上下文后超过 256、未超 H，则独立成块；不能据此继续追加下一个段落。
- 末尾编辑导流段在现有简版 HTML 中存在，因此本轮仍完整保留。将来若要清理，应作为提取/正文版本变化单独比较，不能由 chunker 静默删除。

旧版覆盖口径为 1071 个非空白字符，完整简版 HTML 为 1109 个。新增覆盖的是标题和 metadata；法律内容在本文件中仅作为切分样本引用，不作法律事实评估。

## 4. 本次实际完成的核对与未完成项

已完成：三个完整文本与源简版 HTML 去空白后的文字逐字一致；生成源/产物 SHA-256；核对高考 tbody 数据行数为 171。

这项去空白核对仅用于检查规格样例是否漏文字，不能替代将来新版 chunk 的严格空白与范围验收。已有 37/37、36/36 测试属于旧实现。
