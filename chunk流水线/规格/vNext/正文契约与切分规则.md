日期：2026-09-24。规格版本：`vnext-draft-1`。

[项目说明](../../README.md) 和 [样本实测](../../output/vnext_local_h512/comparison.md)。

简版 HTML 仍是固定上游产物，T/映射是共享解析层的派生结果；严格拼回只约束完整正文交付集合，
独立检索视图不参与拼接。H、生产配置及真实搜索效果尚未确定。

本文是下一版实现与验收的依据草案，包含已确认的需求和为使需求可执行而提出的工程规则。配套文本是规格样例，不是新版切分器运行结果；当前两阶段代码和已有输出未改变。

## 1. 已确认的需求与本轮范围

| 项目 | 已确认的要求 |
|---|---|
| 正文还原 | 所有 chunk 的 `text` 按序直接拼接，严格等于固定的规范化正文 |
| 内容保留 | 标题、metadata、表头都参与正文覆盖；不设内容排除清单 |
| 标题分组 | 标题可以与正文同块，优先跟随所属内容，不强制独立成块 |
| metadata | 必须保留；是否独立成块、如何参与检索可另做实验 |
| 预算 | 256 Unicode 字符作为初始目标，含注入上下文，不含图片 URL |
| 结构保护 | 段落、列表项、提示框允许独立超过目标；表格按连续行分组 |
| 绝对上限 | 另定，不能把 512 当作已经确认的值 |
| 对照 | 保留当前 256 硬上限实现作对照；它不是生产基线 B0 |
| 短章节合并 | 默认不跨主题合并，保留实验选项 |

本轮交付规格、三个完整规范化正文样例及来源校验记录。后续再实现正规化模块、类型预算策略和新版验收，不在本轮接入 embedding、混合检索或 GSB。

以下具体空白规则、字段增补、优先级和代码布局属于工程建议，尚未经过新版实现验收，不应标记成既有生产行为。

## 2. 规范化正文是独立、固定的产物

建议管线：

```text
原始 HTML → 现有提取器 → 简版 HTML
                           ↓
                 规范化正文 + DOM/文本位置映射
                           ↓
                   可替换的切分与上下文策略
                           ↓
                  text / contextual_text
```

记规范化正文为 `T`。同一份简版 HTML、同一个规范化版本必须得到相同的 `T`，不随 chunk 大小、标题分组、metadata 分组或上下文策略变化。

还原对象是简版 HTML 的规范化文本，不是原始 HTML 字节、CSS 排版或提取前已删除的导航广告。图片、链接地址和表格合并关系通过结构字段保存，不能靠纯文本还原这些信息。

### 2.1 文本与空白规则（建议）

1. 输入为 UTF-8 简版 HTML；HTML 实体由解析器解码。不做 Unicode NFKC/NFC、大小写、标点或数字改写。
2. 普通文本节点中的连续 ASCII 排版空白（空格、tab、CR、LF、FF）折叠为一个空格；NBSP 等其他 Unicode 字符原样保留。
3. 行内标签只拆壳，不新增分隔符。相邻行内文本合并后再次折叠连续普通空格；保留原有词间空格，不能对每个文本节点分别 `strip()` 后直接相连。
4. `<br>` 转为 LF。普通文本行两端的普通空格去除；块首尾多余 LF 去除，内部显式连续 `<br>` 保留。块尾 `<br>` 与块边界统一为一个分隔换行。
5. 段落、标题、列表项、嵌套段落等有文字的结构子块依 DOM 顺序以一个 LF 分隔。纯图片子块不凭空增加正文空行。
6. 每个有文字的顶层块末尾增加一个 LF；最后一个块也有终止 LF。空文档为 `""`。这些分隔符属于 `T`，计入字符预算。
7. `<pre>` 内保留空白，只将 CRLF/CR 统一成 LF；块外结构分隔符另计。行内 `<code>` 采用普通行内规则。代码块的布局验收需另补样本。
8. 标题按原文出现顺序输出；metadata 容器内各条文字依次输出；不将 metadata 移到文末，也不因检索开关删除它。
9. 列表保留文字及内部段落边界，不自动生成 `1.` 或 `-`。`ol[start/reversed]`、`li[value]` 和层级关系保留在结构映射中；源文本自带的编号原样保留。
10. 链接正文只保留锚文本，URL 留在结构信息中。图片的 `src/alt` 留在资源映射中，不把 alt 或 OCR 自动添加为正文，也不合成“点击某按钮”等原文没有的文字。

### 2.2 表格规则（建议）

- caption、thead、tbody、tfoot 的文字按简版 HTML 中的 DOM 顺序进入 `T`，每份源文字只输出一次。
- 一行内相邻源单元格以 TAB（`\t`）分隔，行间以 LF（`\n`）分隔，空单元格也保留分隔位置。最终顶层表格末尾带一个 LF。
- 单元格内 `<br>` 仍为 LF；因此不能通过 `splitlines()` 统计表格行数，也不能仅解析文本中的 TAB/LF 来推断结构。行、列及单元格范围由 DOM 映射提供。
- `rowspan/colspan` 记录原始坐标和跨度，不把源单元格的文字复制进被覆盖位置。检索需要补齐信息时，只在 `contextual_text` 中补充并记录来源。
- 不将“表头：”这样的提示词写进 `T`；表头原文在其源位置出现一次，续块重复的表头属于上下文。
- 嵌套表格、多级表头、跨行跨列是后续必补验收项。三个当前样本不足以证明这些场景已支持。

### 2.3 分隔符与严格拼接

优先把结构边界的分隔 LF 留给前一块。chunk 的 `text` 必须直接切自 `T`，不得重新序列化、`strip()` 或在拼接时添加换行。不得生成只含分隔符的块。

```python
# offsets 使用 Unicode 码点下标、左闭右开，不使用 UTF-8 字节下标。
assert chunks[0].start == 0
assert chunks[-1].end == len(T)
assert all(a.end == b.start for a, b in zip(chunks, chunks[1:]))
assert all(c.text == T[c.start:c.end] for c in chunks)
assert "".join(c.text for c in chunks) == T
```

空正文时输出空的文本 chunk 序列；独立图片由资源映射交付。块的来源范围必须连续、递增、不重叠。正文 overlap 默认关闭；重复邻文用于检索时放到增强字段或检索返回层。

示例：`T = "小标题\n第一段。\n第二段。\n"`，可切成 `"小标题\n第一段。\n"` 与 `"第二段。\n"`。业务方直接 `join`，既不删换行，也不补换行。

## 3. 原子、保护单元、chunk 分开定义

原子负责位置与类型，保护单元约束切分，chunk 是最终装箱结果。标题成为一个原子，不表示它必须成为一个独立 chunk。

| 类型 | 建议保护单元 | 分组行为 |
|---|---|---|
| 段落 | 一个段落 | 尽量完整；同章节相邻段落可在目标内合块 |
| 列表 | 单个 li（含其嵌套段落） | 不保护整张列表；多个完整 li 在目标内可同块 |
| 提示框 | 一个 note/warning 提示容器 | 整框优先保护；绝对超长才按内部子块降级 |
| 标题 | 标题与其后首个内容单元的关联 | 优先随下文；连续标题可形成待绑定标题链 |
| metadata | 条目或分组，作为实验配置 | 原文始终保留；独立检索模式不得影响还原流 |
| 表格 | 普通情况下至少完整一行 | 连续行装箱；不同表格不共用表头 |
| quote/pre 等 | 暂按有类型的完整单元处理 | 绝对超长时走专门降级并记账，补专项样本 |

建议首版默认不混装正文段落与表格数据行，便于追踪表头来源；这是候选边界规则，不是用户已确认的普遍要求。表头原文优先和首个数据行同块。

## 4. 装箱、预算与例外

设目标 `B=256`，绝对字符上限 `H` 待定且 `H >= B`。两者都以最终 `contextual_text` 的 Unicode 码点数计数，包含正文分隔符和上下文分隔符。

Embedding token 上限是另一道检查，不能用字符数代替；获得实际模型/tokenizer 限制后单独验证最终输入，禁止静默截断。

### 4.1 建议优先级

1. 正文严格覆盖和顺序不可破坏。
2. 绝对上限及模型输入上限不可突破；无合法输出时显式报错并记录文档，不交付静默丢字的“成功”结果。
3. 默认保持章节/伪标题边界，优先标题随下文。
4. 保护段落、列表项和提示框。
5. 在上述条件内尽量满足 256 目标。

### 4.2 具体行为

- 放入下一个完整单元后不超过 B：允许继续装箱，但不跨默认硬边界。
- 多个本来可单独满足 B 的单元合起来超 B：关闭当前块，下一单元另起块；不能借“类型保护”把任意多个段落合成超大块。
- 单个受保护单元含必要上下文后超过 B、但不超过 H：独立成块，记录 `protected_unit`，不继续追加无关内容。
- 标题链与首个内容单元合起来超过 B、但不超过 H：允许视作一个绑定组独立成块，记录 `heading_binding`，其后不继续装箱。这是待实现的优先规则。
- 若标题与正文之间有 metadata，保持顺序，不能跳过 metadata 后把标题和正文拼成不连续的 `text`。可以与邻接 metadata 分组；是否继续容纳正文由预算和 metadata 分组策略决定。记录标题关联受阻原因。
- 连续普通表格行按 B 分组；单行超 B 时按单元格边界、单元格内句界继续拆，原文切片不重复其他列。续块通过行/列映射与检索上下文维持对应关系。
- 受保护单元超过 H：先拆内部子段落/列表子项，再按句界、分号、逗号/顿号，最后硬断；每次拆分记录原因和来源范围。
- 若最终上下文或分隔符造成超限，必须在输出前再次校验，不能只检验装箱前的原子长度。
- 标题绑定遇到 H、metadata 隔离或异常空章节时允许例外，但必须计入 `orphan_heading` 并附原因，不能为消除孤立标题而改顺序或丢文字。

H 未定时，只可生成带明确状态的实验/规格预览，不能声称已经满足生产长度限制。待真实数据和 embedding 限制确定后再冻结生产配置。

## 5. 检索上下文不改变正文

`text = T[start:end]`；`contextual_text` 为结构化来源生成的前缀与 `text` 的组合。没有额外上下文时二者相等。

- 默认候选：文档标题、当前祖先标题路径、对应表头。不加兄弟章节标题。
- 若标题/表头的源范围已经在当前 `text` 内，避免重复注入同一源内容；判断依据是来源范围，不是简单字符串查重。
- 多级路径设置独立上下文预算；裁剪只能影响注入副本，不删 `T` 中的标题。先保留何层属于可实验策略，暂沿用已有“逐级丢深层”作为对照，不宣称最优。
- LLM 增强作为独立实验因素，记录模型、prompt 版本和缓存键；生成文字只进上下文。最终生成后重新计数，不能将增补后超限的块直接送入模型。
- 单行拆分时如需重复其他列的值，只能放入上下文；原始行的每个字符在 `text` 中仍只出现一次。
- 表头/上下文本身过长时，先按明确优先级裁剪可选前缀；必要表格对应关系仍无法在限制内表达时，标记不可处理并留坏例，不默默去掉关系后当成成功。
- metadata 的“保留”“分组”“是否索引”“是否重复注入”是四个独立维度。若将某些块排除索引，完整正文交付仍需提供全部有序块；不得只将可检索子集交给拼接业务方。

## 6. 输出与可追溯字段（建议增补）

保留当前 JSONL 字段，新增内容按 schema 版本演进。下面是建议，不代表现有代码已经输出。

| 位置 | 字段或信息 | 目的 |
|---|---|---|
| 文档 manifest | `schema_version / extractor_version / normalizer_version / chunker_version / config_hash` | 区分算法与数据版本 |
| 文档 manifest | 输入 HTML 哈希、规范化正文哈希及字符数 | 固定实验输入，核验还原对象 |
| chunk | `start / end` | 精确字符范围，覆盖校验不再只比较 atom_id |
| chunk | `over_target / over_target_reason / absolute_limit` | 分开记录允许的目标超限和禁止的绝对超限 |
| chunk 或侧表 | 单元范围、父结构 ID、行列位置及 rowspan/colspan | 支持结构回溯和表格续块 |
| chunk 或侧表 | 上下文来源范围、裁剪记录、生成版本 | 解释上下文从哪来、删了什么 |
| 资源侧表 | 图片 src/alt、链接目标、DOM 锚点及插入位置 | 无文字资源也不消失 |

现有 `parent_id` 继续表示降级后续块对应的首块，不兼作章节父节点；章节/表格父结构需另存。一个块可能覆盖多个单元的局部，因此完整来源关系以范围侧表为准，不能仅靠块首原子推断。

建议报告：严格还原是否成功、目标超限率及原因、绝对超限数、长度 p50/p95/p99/max、保护单元被拆数及原因、孤立标题及原因、表格行/单元格覆盖、跨章节块数、上下文占比、裁剪次数和块数变化。

## 8. 验收标准与对照安排

### 8.1 新版必须满足

1. **严格覆盖**：`join(text) == T`，包括全部空白；不预先去标题、metadata、thead，不忽略 `|` 或其他字符。
2. **范围覆盖**：各范围从 0 连续覆盖至 `len(T)`，逐块与源切片相等，顺序及 prev/next 链正确。
3. **上下文隔离**：新增标题前缀、重复表头和 LLM 文字不进入 `text`；`contextual_chars` 与最终字符串一致。
4. **结构保护**：只有目标超限时不拆受保护单元；超过 H 才触发有记录的降级；标题绑定的例外有原因。
5. **表格覆盖**：全部原始表头、数据行、caption/tfoot 依源顺序覆盖一次；长行拆分不复制其他列到正文。
6. **预算**：允许的目标超限可解释，最终绝对超限为零；token 上限另验。不能把“多数块不超”当作硬限制合格。
7. **配置有效**：未实现的 `token/llm/soft-budget` 等配置应显式拒绝或标记未支持，不能只进入 hash 而不影响行为。
8. **资源保留**：纯图片块虽无正文，资源映射仍可定位；输入顺序和关联不因块被重组而丢失。

### 8.2 补充样本

- 短标题 + 超目标但未超 H 的长段落；多级超长标题；标题与正文间有 metadata。
- 超 H 的提示框/列表项；无标点长文本；边界处引号与括号；中英文跨行内标签空格；emoji；pre/code。
- 长表头、无表头、超长行、多个长单元格、跨行跨列、多级表头、caption/tfoot、嵌套表格。
- 文本中的字面 `|`、TAB、NBSP、连续 `<br>`；纯图片页与空正文。

### 8.3 冻结与公平比较

- 当前两个原型及其 37/37、36/36 验收保留，标记为旧契约；新版另建验收。旧版通过不等于新版严格覆盖通过。
- 当前实现应冻结代码哈希、配置、输入/输出哈希和依赖版本；这项冻结工作尚未在本规格交付中完成。
- **生产 B0**：来自用户的生产装箱代码、配置和实际结果，尚未导入本目录；不能用当前结构切分原型冒充。
- **旧原型对照**：保留原行为用于回归和历史对比，明确其正文缺项。
- **同正文硬预算对照**：后续在相同 T 上实现 256 硬预算，与新类型保护策略比较，才能单独归因预算策略收益。
- 结构、上下文和预算分别作为实验因素。修复正文缺失后直接与旧原型比较，不能把全部收益都归因于“类型保护”。

## 9. 后续实现顺序

1. 按本文建立规范化模块、字符坐标和资源/结构侧表，用三个样例作固定参照。
2. 冻结旧原型；在单项目中引入策略接口与配置，分别实现同正文硬预算和类型保护候选。生产入口只加载胜出配置和固定版本。
3. 补真实长度分布，获取 embedding 输入限制，确定 H；先在本地输出逐块对比及例外报告。
4. 引入生产 B0、真实 query/网页和固定检索配置，开展切分诊断、chunk 召回、页面排序评测，晋级候选送 GSB。

当前不承诺具体 H、新版块数或搜索收益；这些都需要对应数据。缺少外部数据不影响先实现规范化和范围验收。
