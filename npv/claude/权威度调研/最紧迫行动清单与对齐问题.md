# 网页权威度：最紧迫行动清单与对齐问题

- 日期：2026-09-05
- 配套主报告：`网页权威度方案调研报告.md`（同目录），本文只讲"接下来做什么"和"需要你拍板什么"。
- 排序原则：**先能度量，再改模型；先补零成本信号，再上学习组合。** 每项给出目标、做法、验收标准、大致工作量（以一名熟悉 Spark 与数据的工程师计）、依赖。

---

## 一、最紧迫行动清单

### 第一梯队：两周内（不改模型设计）

**1. 一页纸"权威度定义与用途"**
- 目标：明确分数给谁用、什么粒度、什么刻度，避免后面所有工作对着错误目标优化。
- 做法：回答本文第二部分的问题 1~3，写成一页文档，列出 3~5 个"必须排对"的正反例站点。
- 验收：产品/算法/工程三方签字确认。
- 工作量：0.5 天 + 你的确认。依赖：无。**这是唯一一项需要你先拍板的。**

**2. 跑通修复版，拿到可复现基线**
- 目标：有一个"当前模型到底输出了什么"的事实底座。
- 做法：在原环境编译 `claude/fixed/` 两个文件；同一份输入跑旧版与修复版；输出分布对比（分位数、直方图）、各特征缺失率、NaN/坏行数、每条 pc 规则命中率、`sprMax` 实际值、缺失 pct/pt 的比例。
- 验收：一份基线报表 + 两版分数差异的解释。
- 工作量：2~3 天。依赖：原项目构建环境。

**3. 标注集 v0 与离线评测脚本**
- 目标：让"更准"可度量。
- 做法：
  - 分层抽样约 1,000 个站点 + 1,000 个页面（按 `sr/spr` 分位、区域、类别 1/2/5 与否分层，头部与尾部都要有）。
  - 写一页简化标注指南：站点权威 5 级（官方/权威机构、知名专业来源、普通正规站、低质/采集、垃圾/欺诈），页面质量 5 级；参照 Google 评分员指南 3.3（声誉调研）、3.4（E-E-A-T）与百度优质内容五维度；YMYL 单独标记。
  - 先用 LLM 预标全部样本（提示词包含站点首页、about 页、外部提及摘要），人工复核 200~300 个高风险样本（LLM 高分但流量低、LLM 低分但在白名单等）。
  - 评测脚本输出：Spearman、成对准确率、top-100/bottom-100 精度、标注者一致性。
- 验收：基线在 v0 上的指标数字；标注者一致性 α ≥ 0.6。
- 工作量：5~7 天（含标注）。依赖：可用的 LLM；1~2 名复核人。

**4. 站点级种子表 v1**
- 目标：把散落的白名单/黑名单/官网表整合成"正种子/负种子"两张表，为信任传播做准备，同时立刻修正现有匹配错误。
- 做法：
  - 正种子：`.gov.cn`、`.edu.cn`（修掉 `.edu.com`）、网信办稿源名单 1,358 家（需把单位名映射到域名）、官网表 `owBC`、百科类、国际 `.gov/.edu`。
  - 负种子：`OW_BLACKLIST`、已有垃圾/采集/镜像判定、Safe Browsing 类威胁情报（如可用）。
  - 匹配统一改为"按域名标签逐级剥离查表"（解读报告 4.2 第 2 条），消除 `endsWith` 无边界与 `url.contains` 的误命中。
- 验收：种子表带来源与更新时间字段；抽查 100 个匹配结果无误命中。
- 工作量：3~4 天。依赖：无。

**5. 弄清 `sr/spr` 是什么**
- 目标：权重最大的两个特征至今来源不明，必须搞清楚。
- 做法：下载 Common Crawl 最新域名排名（`cc-main-2026-jun-jul-aug-domain-ranks.txt.gz`，含 PageRank 与调和中心性），与内部 `sr/spr` 按域名 join，算相关性与分布；同时找上游确认 `sr/spr/dr/adc` 的生成逻辑与量纲。
- 验收：一页说明：`sr/spr` 各是什么、与外部链接权威的相关系数、是否需要替换或补充。
- 工作量：2 天。依赖：能访问 Common Crawl 数据（约几 GB）。

### 第二梯队：一到两个月（补最缺的信号）

**6. 信任传播分 `trust_score`**
- 做法：在站点图上跑 TrustRank（正种子）与 Anti-TrustRank（负种子），合成一个 0~1 的信任分。内部有站点级链接图就用内部图；没有则先在 Common Crawl 域名图上验证方法与收益。
- 验收：在标注集上，用 `trust_score` 替换 `ow` 后 Spearman 提升；垃圾站 bottom 精度提升。
- 工作量：1~2 周。依赖：链接图；Spark GraphX 或等价图计算。

**7. 页面级质量特征与页面类型**
- 做法：在解析流水线中产出 Bendersky 十特征（可见词数、标题词数、平均词长、锚文本占比、可见文本占比、熵、停用词占比、停用词覆盖、URL 深度、表格文本占比）+ 广告占比 + 是否有作者/发布时间；把 `pc` 位标记 if-else 链改成带语义的有序规则表；训练一个页面类型分类器（首页/正文/列表/论坛/用户页/新闻）。
- 验收：页面质量 5 级标注上的 Spearman；`pc` 每一位有文档。
- 工作量：2~3 周。依赖：解析流水线可加字段；`pc` 位语义文档。

**8. 身份与合规特征**
- 做法：ICP 主体类型（政府/事业单位/企业/个人/无备案）、域名年龄、HTTPS；新域名（如 < 180 天）先降权。
- 验收：特征覆盖率 > 90%；对垃圾/欺诈站的 bottom 精度提升。
- 工作量：1 周。依赖：ICP/WHOIS 数据源。

**9. 评测与健康度自动化**
- 做法：作业结束自动输出第 3 项的指标、特征分布、规则命中率、缺失率、与上期的名次变动分布，落到固定目录。
- 验收：连续两期报表可对比。
- 工作量：3 天。依赖：第 2、3 项。

### 第三梯队：一个季度（数据驱动的组合）

**10. 学习组合与分层输出**：用标注集训练 LR 或 GBDT 替代 60/12/4/4；输出 `site_authority`、`page_quality`、`npv`（0~100 校准）与特征 JSON；时间因子独立输出交给排序层；新页面无页面信号时继承站点分。
**11. 行为信号**：站点级点击满意度、浏览器流量等级或直接访问占比（视数据可得性与合规）。
**12. LLM 站点评级试点**：对头部约 5 万站点用 LLM 给 0~5 分与理由，作为特征并校准偏高倾向；与人工复核对比。
**13. YMYL 严格模式与治理**：医疗/金融/法律/政务单独阈值；白名单/黑名单/申诉/清零流程；配置外置、参数校验。

## 二、需要与你对齐的问题

每个问题附上我的默认假设。**若你不回复，我会按默认假设推进**，但默认假设错了会导致第一梯队的第 1、3 项方向偏差。

1. **分数的消费方是谁？**（主搜排序先验 / 高质量网页库筛选 `isScroll=1` / AI 搜索与 RAG 的来源过滤 / 爬取调度 / 多个都要）
   默认假设：主搜先验 + 高质量网页库筛选，AI 搜索来源过滤是下一阶段需求。

2. **站点级与页面级要分开输出吗？** 现在只有一个 `npv`。
   默认假设：分开输出 `site_authority` 与 `page_quality`，再合成 `npv` 兼容下游。

3. **YMYL 领域是否需要单独更严格的模型或阈值？**
   默认假设：需要，第三梯队实施。

4. **手头有哪些数据？** 请逐项回答有/无/能拿到：
   - 站点级或页面级链接图（入链、出链）
   - 用户行为日志（搜索点击、浏览器访问、停留、返回结果页）
   - 站点元数据（ICP 备案、WHOIS、HTTPS、域名年龄）
   - 正文解析特征（广告占比、作者、发布时间、页面类型）
   - 已有的垃圾/采集/镜像判定
   默认假设：链接图与解析特征有，行为日志与 ICP 需要申请。

5. **`sr`、`spr`、`dr`、`ow`、`adc`、`pc` 各位的定义与来源？** 谁维护、多久更新？
   默认假设：`sr` 是 0~100 的站点等级，`spr` 是站点级 PageRank，`dr` 是 1~3 的人工站点分级，`adc` 是上游权威站点等级；`pc` 位语义需要文档。

6. **规模与频率？** URL 量级、站点量级、当前作业运行周期、Spark 资源上限。
   默认假设：URL 十亿级、站点千万级、周更。

7. **标注资源？** 有没有评估团队或众包预算？可否调用内部 LLM 批量标注？
   默认假设：无专职评估团队，可用内部 LLM 预标，人工复核由团队成员分担。

8. **技术约束？** 必须 Java/Spark？可否用 GraphX 做图传播、用 Python 训练组合模型再导出参数？
   默认假设：可以。

9. **外部数据源能否用于生产？**（Common Crawl、Tranco、CrUX、维基百科、网信办名单）合规与许可有无限制？
   默认假设：可用于离线校验与冷启动，生产使用需另行确认。

10. **当前最痛的坏例子是什么？** 低质站排太高、官方站排不上、采集镜像站、还是别的？有没有一批 bad case 列表？
    默认假设：低质/采集站得分偏高与官方站覆盖不全并存；标注集 v0 会同时覆盖两类。

11. **区域范围？** 只做 `zh` 还是多区域？多区域时种子表与 YMYL 定义要分区域维护。
    默认假设：`zh` 优先，其他区域沿用现有 `.gov/.edu` 逻辑。

12. **两周内的目标是什么？** 是先出基线与标注集（我的建议），还是先上一个改动最小的分数版本？
    默认假设：先基线与标注集。
