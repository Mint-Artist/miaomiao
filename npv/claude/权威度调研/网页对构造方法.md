# 网页对构造方法（2026-11-23，同日修订：加入 10 页以上的站点）

- 用途：把已经抽好的样本配成约 2 万个网页对，交给大模型两两比较，用来拟合 NPV 打分公式。
- 状态：Claude 提出的方案，待用户确认后执行。
- 前一份文档：`网页对数据集抽样方案.md`（怎么抽页面）。本文接着讲怎么配对。

## 1. 现有样本

抽样规则修改后，页面多的站点可以抽到 10 页以上。下表前四行是修改前的数，最后一行的数待补：

| 站点类型 | 站点数 | 页面数 |
| --- | --- | --- |
| 单页 | 1800 | 1800 |
| 2 页 | 500 | 1000 |
| 3 页 | 297 | 891 |
| 4 页 | 3391 | 13,564 |
| 5 页以上（主要是大站） | 待补 | 待补 |

下文的规则按"站点有几页"来写，对任何页数都适用。拿到新的分布后，按第 5、6 节的公式重算对子数即可。

**为什么大站要多抽页面**：大站内部差别大，同一个域名下可能既有编辑部的稿件，也有自媒体账号、论坛、问答、软文（例如财富号这类子版块）。只抽几页看不出这种差别。多抽的页面主要用来配站内对，让公式学会区分同一站点里的好页面和差页面。

## 2. 目标

| 对子 | 数量 | 用途 |
| --- | --- | --- |
| 站内对 | 约 7600，加上大站带来的部分 | 两页来自同一站点。站点特征相同，只比页面，用来定页面特征的权重（正文长度、页面类型、时效等） |
| 跨站对 | 约 1.2 万 | 两页来自不同站点。用来定站点特征的权重，以及站点与页面两部分的比例 |
| 合计 | 约 2 万 | 大站多了以后会超过 2 万，超出的部分可以放进第 3 批，或按第 6.1 节调低名额 |

## 3. 准备工作

### 3.1 每页需要的字段

网址、站点、站点的 sr、标题、正文、正文长度、页面类型相关字段、发布时间。有主题信息的话（如 mdc 归成的主题大类）也带上。

### 3.2 站点表

每个站点一行：站点、sr、页面数、划分。

- **站点口径**与 sr 一致。sr 按主域名给就按主域名，按子域名给就按子域名。
- **sr** 取该站点页面 sr 的中位数（同一站点的 sr 一般相同）。

### 3.3 划分

站点按 6:2:2 分成训练、调参、测试三份：

```
划分 = 由 md5(站点名) 的前 8 位换算成 0~1 的数决定：< 0.6 为训练，< 0.8 为调参，其余为测试
```

- 同一站点的所有页面只在一份里。
- 用站点名的哈希来分，以后追加站点时，已有站点的划分不会变。
- 分完检查一下：三份里各 sr 段的站点数比例应大致相同。

### 3.4 去掉不能配对的页面

- **抓取失败、正文为空、错误页**：不参与配对，单独记一份清单。
- **同一站点内正文几乎相同的页面**（标题相同或正文哈希相同）：只留一页。
- **不同站点之间正文几乎相同的页面**（转载）：不配成一对。

视频页、短页不要去掉。

## 4. 每页的使用次数

| 对子 | 每页最多 |
| --- | --- |
| 站内对 | 1 次 |
| 跨站对 | 2 次 |

一个页面最多出现在 3 对里。大站的页面多，跨站名额有上限（见 6.1），所以大站的页面在跨站对里平均用得少，主要用在站内对上。

## 5. 站内对怎么配

**规则：一个有 n 页的站点配 n÷2（向下取整）个站内对，每页只用一次。**

| 站点页数 | 配几对 |
| --- | --- |
| 1 页 | 0 |
| 2 页 | 1 |
| 3 页 | 1（三页里取两页） |
| 4 页 | 2 |
| 10 页 | 5 |
| n 页 | n÷2，向下取整 |

合计 = 所有站点的 n÷2 之和。修改前的样本是 500 + 297 + 3391 × 2 = 7579 对；每多一个 10 页的站点，多 5 对。

**怎么分成对**，按划分区别对待：

- **调参、测试站点**：把页面随机打乱，相邻两页配一对。评测要反映真实情况，不能挑。
- **训练站点**：让每对里的两页差别尽量大，这样能学到更多。
  - 4 页以内的站点：试遍所有分法（4 页只有 3 种），选总差别最大的。差别用正文长度对数之差的绝对值，加上页面类型是否不同来算。
  - 5 页以上的站点：分法太多，不必试遍。按正文长度从短到长排好，第 1 页配第 (n÷2 + 1) 页，第 2 页配第 (n÷2 + 2) 页，依此类推，也就是短的一半和长的一半一一配对。
  - 大站另加一条：能分出子域名或栏目的（例如路径第一段不同），优先让一对里的两页来自不同子域名或栏目。子版块之间的差别正是大站最需要学的。

**大站的站内对要不要多配**：每页只用一次时，10 页的站点配 5 对，已经比小站多。如果标完第一批后发现页面特征的权重仍然定不准，可以只对大站放宽到每页用 2 次，10 页的站点最多配到 10 对。

## 6. 跨站对怎么配

### 6.1 每个站点进几个跨站对

**规则：名额 = 2 × 页数，最多 5 个。**

| 站点页数 | 跨站对名额 |
| --- | --- |
| 1 页 | 2 |
| 2 页 | 4 |
| 3 页及以上 | 5 |

大站的名额也是 5，不随页数增加。跨站对是用来比较站点的，每个站点无论大小只代表一个站点，给大站更多名额会让少数大站主导站点权重。

名额合计 = 所有站点的名额之和；每个跨站对占两个名额，跨站对数约为名额合计的一半。修改前的样本是 1800 × 2 + 500 × 4 + 297 × 5 + 3391 × 5 = 24,040，约 1.2 万对；每多一个大站，多 2.5 对。

如果总对数明显超出预算，优先调低 3 页及以上站点的名额（例如 5 改成 4），不要减站内对。

### 6.2 两个站点的 sr 差多少

按两个站点的 sr 之差分四档，目标比例如下：

| sr 之差 | 目标比例 | 约多少对 | 作用 |
| --- | --- | --- | --- |
| 10 及以下 | 30% | 3600 | 站点接近，主要比页面 |
| 10～30（含 30） | 55% | 6600 | 主力，定站点权重最有效 |
| 30～50（含 50） | 10% | 1200 | 补充 |
| 50 以上 | 5% | 600 | 检查用，结果应该几乎总是高 sr 一方胜 |

这个比例是初定的。第一批标完后看各档里"sr 高的一方赢"的比例：某一档已经接近 100%，就少配；某一档接近 50%，说明这一档主要在比页面，也可以少配一点。

### 6.3 其他规则

- **只在同一划分内配。** 训练站点只和训练站点配，测试站点只和测试站点配。
- **同一对站点只配一次。**
- **有主题信息时优先同主题大类。** 目标是跨站对里七成以上同主题。凑不到同主题的，允许不同主题。
- **页面选用得少的。** 一个站点有多页时，轮流用，不要总用同一页。

### 6.4 配对步骤

在每个划分内分别做：

1. 列出所有站点和它们剩余的跨站名额。
2. 按 6.2 的比例算出每一档还要配多少对。
3. 取剩余名额最多的站点 s（并列时随机）。
4. 选一档：在还没配满的档里，按剩余数量的比例随机选。
5. 在同一划分里找候选站点 t：sr 之差落在这一档、还有名额、没和 s 配过。有主题信息时，先找和 s 的待用页面同主题的。
6. 从候选里随机取一个，名额越多越容易被选中。
7. s 和 t 各取一个用得最少的页面，配成一对，两边名额各减一。
8. 如果这一档找不到候选，换一档；所有档都找不到，s 剩下的名额作废。
9. 重复到名额用完或配不出为止。

最后会有少量名额配不出去，主要是最高和最低 sr 段的站点。数量不大就不用管。

## 7. 顺序与标注

- 每对里哪一页做 A、哪一页做 B，随机定。
- **两种顺序各判一次**，两次的原始结果都保留，各占一行。不要再用"两次相反就废弃"的规则：被废弃的正好是两页最接近的对子。
- 判官输出 A 更权威、B 更权威、相当、不可比四种之一。不可比要给原因。
- 不可比的结果也保留，事后统计它们集中在哪里。

## 8. 分批标注

先给每个对子分配批次，按划分和对子类型分组后随机分：

| 批次 | 比例 | 累计约 |
| --- | --- | --- |
| 第 1 批 | 25% | 5000 对 |
| 第 2 批 | 25% | 1 万对 |
| 第 3 批 | 50% | 2 万对 |

每标完一批拟合一次。如果第 2 批和第 3 批拟合出的权重、各部分的贡献占比基本一样，说明已经够了，可以停。

**人工标注**：从第 1 批里抽 400 对，站内、跨站各一半，并有意包含一些正文长度相差很大的对子和 sr 相差很大的对子。人工看的内容和判官看的一样，两种顺序不用都看。

## 9. 输出文件

`pairs.tsv`，每对一行：

| 列 | 说明 |
| --- | --- |
| pair_id | 对子编号 |
| url_a、url_b | 两个页面 |
| site_a、site_b | 两个站点 |
| sr_a、sr_b | 两个站点的 sr |
| sr_gap | sr 之差的档：10 及以下、10～30、30～50、50 以上（含右端点）；站内对填"站内" |
| type | 站内 或 跨站 |
| split | 训练、调参、测试 |
| same_topic | 是否同主题大类，没有主题信息时留空 |
| purpose | 随机 或 挑选（训练站点的站内对是挑选） |
| batch | 1、2、3 |
| human | 是否抽进人工标注 |

标注结果另存 `labels.tsv`，每次判定一行：pair_id、顺序（AB 或 BA）、结论、不可比原因、判官模型版本、prompt 版本、时间。

两份文件生成后冻结。以后追加站点只追加行，不改已有的行。

## 10. 配完后的检查

| 检查项 | 期望 |
| --- | --- |
| 对子总数 | 站内 = 各站 n÷2 之和；跨站 ≈ 名额合计 ÷ 2 |
| 大站 | 每个大站的站内对 = 页数 ÷ 2，跨站对不超过 5 |
| 各划分的对子数 | 约 6:2:2 |
| 跨站对的 sr 之差分布 | 接近 6.2 的目标比例 |
| 跨站对的同主题比例 | 七成以上（有主题信息时） |
| 每页的使用次数 | 站内不超过 1，跨站不超过 2 |
| 没有进入任何对子的站点 | 只应是页面全被去掉的站点 |
| 跨划分的对子 | 0 |
| 同一对站点重复 | 0 |

## 11. 附：跨站配对的示意代码

只示意第 6.4 节的逻辑。在合成数据上跑过：页数分布取修改前的样本，再加 300 个 10 页站点和 50 个 15 页站点，sr 随机。结果是站内对 9429、跨站对 12,891，跨站对四档分别是 3868、7092、1286、645；大站的跨站对都不超过 5 个，没有跨划分的对子，每页在跨站对里最多用 2 次。没有在真实数据上运行。真实数据的 sr 集中在中段，两端的站点可能配不满。

```python
import random
from collections import defaultdict

BUCKETS = [(0, 10, 0.30), (10, 30, 0.55), (30, 50, 0.10), (50, 100, 0.05)]   # 左开右闭，第一档含 0

def bucket_of(d):                       # sr 之差落在哪一档；sr 取中位数后可能带小数
    return 0 if d <= 10 else 1 if d <= 30 else 2 if d <= 50 else 3

def quota_of(n_pages):
    return min(2 * n_pages, 5)            # 1 页 2 个，2 页 4 个，3 页及以上 5 个

def cross_pairs(sites, pages_of, split_of, sr_of, topic_of=None, seed=0):
    """sites：站点列表；pages_of[s]：站点 s 的页面列表；split_of[s]：取 train/dev/test（即训练/调参/测试）；sr_of[s]：站点 sr；
    topic_of[p]：页面主题大类（可选）。返回 [(页面 a, 页面 b, 档位)]。"""
    rng = random.Random(seed)
    out = []
    for split in ("train", "dev", "test"):
        S = [s for s in sites if split_of[s] == split]
        left = {s: quota_of(len(pages_of[s])) for s in S}
        use = defaultdict(int)                       # 页面在跨站对里用了几次
        total = sum(left.values()) // 2
        need = [round(total * w) for _, _, w in BUCKETS]
        done = set()

        def free_page(s, topic=None):
            cand = [p for p in pages_of[s] if use[p] < 2]
            if topic_of and topic is not None:
                same = [p for p in cand if topic_of[p] == topic]
                cand = same or cand
            return min(cand, key=lambda p: (use[p], rng.random())) if cand else None

        while True:
            active = [s for s in S if left[s] > 0]
            if len(active) < 2 or sum(need) == 0:
                break
            s = max(active, key=lambda x: (left[x], rng.random()))
            pa = free_page(s)
            order = [k for k in range(len(BUCKETS)) if need[k] > 0]
            rng.shuffle(order)
            order.sort(key=lambda k: -need[k] * rng.random())
            paired = False
            for k in order:
                cand = [t for t in active if t != s and (min(s, t), max(s, t)) not in done
                        and bucket_of(abs(sr_of[s] - sr_of[t])) == k]
                if topic_of and pa is not None:
                    same = [t for t in cand if any(topic_of[p] == topic_of[pa] and use[p] < 2 for p in pages_of[t])]
                    cand = same or cand
                if not cand:
                    continue
                t = rng.choices(cand, weights=[left[x] for x in cand])[0]
                pb = free_page(t, topic_of[pa] if topic_of and pa is not None else None)
                if pa is None or pb is None:
                    continue
                a, b = (pa, pb) if rng.random() < 0.5 else (pb, pa)
                out.append((a, b, k))
                use[pa] += 1; use[pb] += 1
                left[s] -= 1; left[t] -= 1
                need[k] -= 1
                done.add((min(s, t), max(s, t)))
                paired = True
                break
            if not paired:
                left[s] = 0                          # s 配不出去了，剩余名额作废
    return out
```
