## 一、输入文件 `input.tsv`

一行一个 URL，制表符分隔，**至少 6 列**，只有第 0、2、5 列被读取。

| 列下标 | 内容 | 类型 | 是否必需 | 用途 | 缺失或异常时 |
| --- | --- | --- | --- | --- | --- |
| 0 | url | 字符串 | **必需** | 解析出站点后查 dr 站点表、dr 后缀表、官网表、官网黑名单；整个 URL 做 adc 白名单子串匹配；页面类别规则里匹配 `news`（不分大小写）、`/u/`、`/user/`（区分大小写） | 不能为空 |
| 1 | 任意 | | 占位 | 代码不读 | 填任意值，不能省略这一列 |
| 2 | 类别标记 | 字符串 | `--scroll 1` 时必需 | 取值为 `1`、`2`、`5` 的行视为"高质量网页"，进入排名归一化输出 `npv`；其余进入 `npv_ori` | `--scroll 0` 时可填任意值；含义需你确认（代码里变量名 hqw） |
| 3、4 | 任意 | | 占位 | 代码不读 | 填任意值 |
| 5 | 特征 JSON | JSON 对象字符串 | **必需** | 见下表 | 非法 JSON：原逻辑整个作业失败；修复版跳过该行并计数 |
| 6 及以后 | 任意 | | 可无 | 代码不读 | |

### 第 5 列 JSON 的字段

| 字段 | 类型 | 含义（按代码用法推断） | 取值要求 | 对分数的作用 | 缺失或异常时（原逻辑 / 修复版） |
| --- | --- | --- | --- | --- | --- |
| `sr` | 整数 | 站点等级 | 预期 0 到 100；负数表示缺失 | `sr/100` 与 spr 合成 spr_sr，权重 60，是分数的主体 | 键缺失：整体失败 / 该行跳过。负数：spr_sr 固定取 0.25（两版相同） |
| `spr` | 浮点 | 站点级第二个分数 | ≥ 0；负数会被钳到 0 | 除以全库最大值 sprMax 后参与 spr_sr | 键缺失：整体失败 / 该行跳过 |
| `adc` | 字符串，内容是 JSON `{"level": N}`，或空串 `""` | 权威站点等级 | `level` 为整数 0 到 3 | ≥ 2 跳过页面类别与 pt 衰减；2 加 10 分、3 加 15 分；0 时再看 adc 白名单 | 键缺失：整体失败 / 视为 0。空串：视为 0。`level` 缺失：两版都失败/跳过 |
| `pcLong` | 长整数 | 页面类别位图 | 读取的位：10、11、13、16、18、19、20、22、24、26、29、32、33、38 | 位 20 保底 60 分；其余按优先级取第一个命中的位乘 0.6 到 0.9 | 缺失或非数字：视为 0，不做任何页面类别调整（两版相同） |
| `pct` | 整数时间戳 | 页面时间之一（含义待确认） | 10 位秒或 13 位毫秒 | 全部页面按 2000 天尺度衰减 | 缺失或 0：原逻辑按 2024-05-22 到今天衰减（今天约 0.79）/ 修复版不衰减。位数不是 10 或 13：原逻辑解析出离谱日期 / 修复版不衰减 |
| `pt` | 整数时间戳 | 页面时间之二（含义待确认） | 同上 | adc < 2 的页面按 3000 天尺度衰减 | 缺失或 0：两版都不衰减 |
| `pureTextLen` | 整数 | 正文长度 | ≥ 0 | < 300 乘 0.8，< 500 乘 0.9 | 键缺失：整体失败 / 该行跳过 |

**需要你确认的三点**：`sr` 和 `spr` 的实际量纲与缺失约定（是否用 -1）；`pct` 与 `pt` 哪个是抓取时间、哪个是发布时间；第 2 列 `1`、`2`、`5` 的含义。

## 二、六张表

全部为 UTF-8 文本，制表符分隔。**用线上完整表，不要抽样**，否则查不中会全部退化成默认值。

| 文件 | 格式 | 键的形式 | 用法 | 是否可为空文件 | 注意 |
| --- | --- | --- | --- | --- | --- |
| `spr.tsv` | `站点 \t spr值` | 任意 | **只用第 2 列求全库最大值 sprMax**，站点名不参与 | 不可：原逻辑与修复版都报错 | 最大值必须 > 0，否则原逻辑产出 NaN、修复版报错退出。这张表的最大值应与线上作业启动时的一致，否则所有页面的 spr 特征等比例偏移 |
| `dr_site.tsv` | `站点 \t dr值` | 站点，须与 `parse_site` 的输出形式一致（是否带 www、是否小写） | 精确匹配站点 | 可 | dr 值预期 1 到 3，除以 3 |
| `dr_suffix.tsv` | `域名后缀 \t dr值` | 后缀，用 `endsWith` 匹配（如 `gov.cn` 或 `.gov.cn`，需确认线上写法） | 站点表未命中时按后缀匹配，取第一个命中 | 可 | 若存在互相包含的键（如同时有 `edu.cn` 和 `cn`），命中顺序取决于 Java HashMap，npv_exact 结束时会报告这类行数 |
| `ow.tsv` | `站点 \t 值` | 站点 | 值 > 0 视为官网，ow 特征取 1，权重 4 | 可 | 值必须能解析为数字 |
| `ow_blacklist.txt` | 每行一个域名后缀 | 后缀 | `endsWith` 命中则 ow 取 0 | 可 | **不能有空行**：原逻辑下空行使所有页面 ow 为 0 |
| `adc_whitelist.txt` | 每行一个子串 | 任意子串 | 在**整个 URL** 上 `contains` 命中则 adc 取 3 | 可 | **不能有空行**：原逻辑下空行使所有页面 adc 为 3，进而全部加 15 分并跳过页面类别调整 |

线上作业启动时会把 `OW_BLACKLIST` 与 `ADC_WHITELIST` 的完整内容以 ERROR 级别打进 driver 日志，若原表不好找可以从任一次历史日志里恢复。

## 三、运行参数

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `--region` | `zh` 或不传 | `zh` 时官网白名单为 `.gov.cn`、`.bendibao.com`、`.edu.com`、`.baike.com`、`baike.baidu.com`；否则 `.gov`、`.edu`。`.edu.com` 疑为笔误，待确认 |
| `--scroll` | 0 或 1 | 1 时按第 2 列拆分并输出归一化等级 |
| `--now` | 秒级时间戳 | 对齐线上时传作业运行当天的时间戳 |
| `--tz` | 如 `Asia/Shanghai` | 集群默认时区，仅 npv_exact 有 |

## 四、用于对齐线上的可选输入

| 输入 | 用途 |
| --- | --- |
| 同一批 URL 的线上 `npv_ori` 输出（url、npv_ori、npv_fea） | 用 `npv_py/compare_with_java.py` 逐条比对，验证复现是否一致 |
| 线上作业当天的日期 | 作为 `--now` |
| 原项目 `ParseSiteUtil.parseSite` 的实现或几个输入输出样例 | 站点解析是唯一无法从代码推出的部分，直接决定四张表能否查中 |

## 五、评估阶段的输入（跑分不需要，做偏序评估时需要）

| 文件 | 格式 | 说明 |
| --- | --- | --- |
| `labels/pairs.tsv` | `url_a \t url_b \t pref \t [group]`，`pref` 为 `a`、`b` 或 `tie` | 大模型或人工的偏序判定；`group` 可填头部/长尾、垂类等 |
| `labels/grades.tsv` | `url \t grade \t [group]`，`grade` 为 0 到 4 | 绝对档位，用于误压率、误抬率与校准曲线 |

标签里的 URL 必须能在 `input.tsv` 中找到，且写法完全一致（协议、大小写、尾部斜杠）。

---

## 六、最小可运行集

只想先跑通流程时：`input.tsv` 提供第 0、2、5 列和占位列；`spr.tsv` 至少一行且值 > 0；其余四张表和两个名单可以是空文件。但这样 dr 全部取默认值 1/3、ow 全 0、adc 只看 JSON 里的 level，分数与线上不可比。

## 七、样本量与抽样建议

几千到一万行即可，一秒内跑完。按站点等级、adc 等级、第 2 列类别分层抽，避免整批来自同一个站。表文件必须完整。
