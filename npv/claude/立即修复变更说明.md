## 修复 1：preProcessPr 区间判断永远为假（P0-1）

**文件** `PageValueScore.java`，原 :102-112 → 新 :111-127

原代码：

```java
if (pr < this.prSplit.get(0)) {
    return 0.01f;
}
for (int idx = 0; idx < this.prSplit.size() - 1; idx++) {
    if (pr > this.prSplit.get(idx) & pr <= this.prSplit.get(idx)) {   // 两边都是 idx，恒为假
        return idx / 100.f;
    }
}
return 1.0f;
```

修改后：

```java
int n = this.prSplit.size();
if (n == 0 || pr <= this.prSplit.get(0)) {
    return 0.0f;
}
for (int idx = 0; idx < n - 1; idx++) {
    if (pr > this.prSplit.get(idx) && pr <= this.prSplit.get(idx + 1)) {
        return (idx + 1) / (float) n;
    }
}
return 1.0f;
```

改动点：

1. 区间上界改为 `prSplit[idx + 1]`，判断真正生效。
2. 返回值由 `idx / 100` 改为 `(idx + 1) / n`，不再假设 prSplit 恰好 100 行；最低区间返回 `1/n`，高于最大切分点返回 1.0，整体严格单调。
3. 低于最小切分点由 0.01 改为 0.0，避免出现"低于最小值的分数反而高于第一档"的倒挂（原来修好区间后 idx=0 会返回 0.0 < 0.01）。pr 权重只有 4，这一改动最多影响 0.04 分。
4. 新增 `n == 0` 保护，prSplit 文件为空时不再抛 IndexOutOfBounds。
5. `&` 改为 `&&`。

**结果影响**：这是行为变化最大的一处。原来所有 `pr >= prSplit[0]` 的页面 pr 特征都是 1.0，现在按分位数落在 (0, 1]，多数页面的 pr 贡献会从 4 分降到 4 × 分位。请用真实数据比对分数分布。

## 修复 3：sortByKey 使用 Tuple2 作键（P0-3）

**文件** `PageValueScoreMain.java`，原 :136-153 → 新 :156-173

原代码把 `(score, url + "\t" + fea)` 组成 `Tuple2` 作为键调用 `sortByKey(false)`，`scala.Tuple2` 未实现 `Comparable`，按 Spark Java API 的实现会抛 `ClassCastException`。

修改后：

```java
JavaPairRDD<Row, Long> rankRdd = rdd
        .sortBy(row -> row.getDouble(1), false, rdd.getNumPartitions())
        .zipWithIndex();
```

- 直接对 `JavaRDD<Row>` 按 `npv_ori`（double）降序 `sortBy`，分区数沿用输入分区数。
- 排序后保留完整 `Row`，输出时用 `row.getString(0)` / `row.getDouble(1)` / `row.getString(2)` 取字段，删除了原来把 url 与 fea 拼成字符串再 `split("\t")` 四次的做法（顺带消除 url 含制表符时的错列风险，也减少了 shuffle 时键的体积）。
- 分桶查找逻辑（线性扫描 `urlIntervals`）与 `1000 - idx` 的映射未改。

**结果影响**：对合法输入，排序结果与原意图一致；并列分数的相对顺序仍不确定（报告 P1-8，属于中期项）。

### 行为差异对照

| 情形 | 原行为 | 新行为 |
| --- | --- | --- |
| pct/pt 为 0 或缺失（`"0"`） | 按 2024-05-22 到今天的天数衰减（今天约 0.79，随日历推移持续下降） | 系数 1.0，中性 |

## 修复 5：单行坏数据导致整个作业失败（P0-6）

**文件** `PageValueScoreMain.java`，原 :91-134 → 新 :103-154

- map 函数体整体包在 `try { ... } catch (Exception e)` 中；任何一行解析或打分抛异常（JSON 非法、字段缺失导致的 NPE、列数不足、level 非数字等）时，`badRows.add(1)` 并 `return null`，交给已经存在的 `.filter(Objects::nonNull)` 过滤。原代码这个 filter 从未生效。
- 顺带补两处最常见的空指针：`adc != null && !adc.isEmpty()`（新 :135）、`pr == null || pr.isEmpty()`（新 :138），让 `pr`/`adc` 字段缺失的行走正常路径而不是被当作坏行丢弃。
- 原有的三个内层 try/catch（pcLong/pct/pt 缺省 0）保留不动。
- 新 :60：新增累加器 `bad_rows`；新 :98-99：作业结束前把 `total_count` 与 `bad_rows` 写入日志（原来 `dataCount` 从未被读出）。

**注意**：`isScroll = 1` 时 `midRdd` 会被计算两次（报告 P2-1，属短期重构项，本次未改），这两个计数可能是实际值的两倍，日志和代码注释里都已注明。
