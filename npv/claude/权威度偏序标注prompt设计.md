# 权威度偏序标注：给大模型什么、怎么问

- 日期：2026-09-14
- 适用：真实引擎 top20 头尾抽页、两两比较权威度的评估方案（见 `npv_lab/README.md` 与记忆里的评估方案）。
- 产出格式对齐 `npv_lab/labels/pairs.tsv`（`url_a url_b pref group`）与 `grades.tsv`（`url grade group`）。

---

## 一、给模型哪些输入

原则：**给它判断权威度真正需要的证据，不给会让它走捷径的东西。** 只给 URL 它就靠品牌印象判，结果和 sr、spr 这些流行度信号是同一个东西，评估会循环论证。

| 输入 | 是否给 | 理由 |
| --- | --- | --- |
| query | **给** | 权威是分主题的：医学站在法律问题上不权威。也用来判"是否切题"这个门槛 |
| 标题 | **给** | 便宜且信息密度高：机构名、标题党、聚合页一眼可见 |
| 正文 | **给，截前 1500 到 2000 字** | 作者署名、机构落款、引用、免责声明、广告和模板文本比例都在正文里；这是区分"大站灌水页"和"小站专业页"的唯一依据 |
| URL 的路径部分 | **给** | `/u/`、`/forum/`、`/tag/`、`/list` 这类路径形态是页面类型的直接线索 |
| 域名 / 站点名 | **分两轮：一轮给，一轮遮掉** | 带域名的一轮衡量"站点声誉加内容"，遮域名的一轮只衡量内容；两轮差值就是名气在判断里占的份额，也是"小站被压"问题的量化答案 |
| 发布时间、作者、机构 等结构化元数据 | 有就给 | 减少模型从正文里猜；没有就让它从正文找 |
| 当前 npv 分数、sr、spr、点击量、排序位置 | **绝不给** | 这是被评估对象或其代理，给了就是泄漏 |
| 页面截图、外链数、备案信息 | 暂不给 | 成本高，先用文本跑通基线；以后可作为第三轮实验 |

正文截取建议：去 HTML 后的纯文本，取开头 1500 字加结尾 300 字（落款、参考文献、免责声明常在尾部），中间用 `……` 标出省略。两页合计控制在 4000 字以内。

---

## 二、怎么问：两两比较的 prompt

要点：判定维度锁死在"来源可信度 + 内容专业性 + 内容质量"，相关性只作门槛不参与胜负，时效性不看；允许"相当"；分维度打分再给结论，便于事后分析；输出严格 JSON。

### System

```
你是搜索质量评估员，任务是比较两个网页在给定查询主题下的权威度。

权威度指：如果两个网页都在回答这个查询，你更信任哪一个网页的信息来源。它由三方面构成：
1. 来源可信度：发布者是谁（政府、机构、企业官方、专业媒体、专家个人、普通用户、内容农场），是否有明确的署名、机构落款、联系方式、资质说明。
2. 内容专业性：是否展现出领域知识，论述是否具体、准确、有依据（数据、引用、法规条文、一手经验），有无明显错误或夸大。
3. 内容质量：是否原创、完整、结构清楚；广告、导流、模板文本、堆砌关键词的比例；是否为列表页、聚合页、用户主页等非正文页。

不要考虑的因素：
- 哪个网页与查询更相关。只需先判断两页是否都基本切题；胜负只比权威度。
- 哪个网页更新。发布时间不影响权威度判断。
- 网页篇幅长短本身。长不等于权威。
- 网页在搜索结果中的位置或任何排名信息。

注意：大型知名站点上也有大量低质量的用户生成内容、聚合页、营销页；小型或不知名站点上也可能有机构官网、专业人士的权威内容。请根据页面本身的证据判断，不要仅凭站点名气。

允许判为"相当"：当两页权威度差别不明显时，选择 tie，不要强行分出高下。

只输出 JSON，不要输出其他文字。
```

```

作者/机构：{author_b 或 "未知"}

请按以下 JSON 格式输出：
{
  "relevance": {"a": 0-2, "b": 0-2},
  "source_credibility": {"a": 1-5, "b": 1-5},
  "expertise": {"a": 1-5, "b": 1-5},
```

### User（遮域名的一轮）

与上面相同，只把两处 `站点：{host}` 改为 `站点：（已隐藏）`，并把正文里出现的站点名替换为 `〔站点名〕`。其余不变。

## 三、调用与落库规则

1. **每对判两次，交换 A、B 顺序。** 两次 verdict 不一致（一次 a 一次 b）的对标为 inconsistent，剔除；一次 tie 一次有偏向的，记为 tie。
2. **相关性门槛。** 任一页 relevance 为 0，或两页 relevance 相差 2，剔除该对；相差 1 的保留但打上 `rel_gap=1` 标记，评估时可单独看。
3. **两轮各自落一份 pairs.tsv。** `pairs_with_host.tsv`、`pairs_blind.tsv`，group 列填 `head`/`tail` 加垂类，如 `head|医疗`。
4. **保存原始 JSON。** 分维度分数以后做误差归因要用：npv 判错的对里，是 source_credibility 反了还是 content_quality 反了，能直接指出该补站点级还是页面级特征。
5. temperature 0，固定模型版本与 prompt 版本号，写进文件名。
6. 三五百对人工复核，算人机一致率，作为指标天花板。

## 四、绝对档位的 prompt（辅助集，算误压率用）

只对单页打分，用于 21 到 50 名随机抽的页面。System 与上面相同，User 只给一页，输出：

```
{
  "relevance": 0-2,
  "source_credibility": 1-5,
  "expertise": 1-5,
  "content_quality": 1-5,
  "page_type": "...",
  "risk": [...],
  "authority_grade": 0-4,
  "reason": "不超过 60 字"
}
authority_grade：0 垃圾或误导；1 低质或不可信来源；2 普通正规来源；3 专业或知名机构来源；4 官方或权威机构来源。
```

`authority_grade` 落到 `grades.tsv`。

---

## 五、几个容易踩的坑

- **把"更好"当"更权威"。** 不锁维度，模型会跟着相关性和可读性走，指标就变成在测引擎的排序而不是 npv。
- **只给 URL。** 模型会说"知乎比小站可信"，这正是要避免的循环。
- **正文没去模板。** 导航、页脚、推荐位占了 1500 字的一半，模型看不到落款和引用。截取前先做正文抽取。
- **强迫二选一。** 前 20 名里很多对本来就分不出高下，强迫选择只增加噪声。
- **让模型看到排名位置。** 头尾对的位置信息一旦泄漏，模型会倾向头部。
- **中途换模型或改 prompt。** 前后批次标签不可比，改了就整批重打。
