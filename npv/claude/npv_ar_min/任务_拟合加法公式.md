# 任务：用偏序标签重新拟合 npv 的加法公式

> 给内网 codeagent 执行的任务书。按步骤做，每步有"验收"。做完按最后一节的模板写报告。

## 背景（读完再动手）

- 线上 npv 是一条手定权重的乘法链公式。现在有一批大模型判官给出的"同一 query 下两页谁更权威"的偏序标签（train 约 1.6 万对，test 约 4 千对，按 query 切分）。
- 已有结果：原公式 test 一致率 0.657；在原公式上手调权重 0.679；xgboost 用约 25 列特征早停后 test 0.734，这是现有字段的上限。
- 目标：**不上树模型**，把公式改成加法形式 `score = max(0, Σ wᵢ·fᵢ)`，权重用偏序逻辑回归拟合，尽量逼近 0.734，并且公式保持短（10 到 15 项）。
- 代码在 `npv/claude/npv_ar_min/`，依赖同级的 `npv_py`、`npv_lab`、`npv_ar`。拟合脚本 `tools/fit_formula.py`，特征定义 `tools/features_v2.py`，评估 `eval.py`。

## 硬性规则

1. **test 集只在第 6 步看一次**，中间所有决策只看 train（以及从 train 里切出来的 dev）。
2. 特征里**不许**出现：线上 npv 分数、排名位置（rank/pos/neg 身份）、pair_id、任何来自判官输出的字段。
3. 评估口径固定：严格一致率 = (判对 + 0.5×同档) / 有方向的对数，打分缺失的对算错；同档 = 等级差 ≤ 50（`data/meta.json` 的 `tie_band`），没有 level_map 时用原始分完全相等。三个模型（原公式、新公式、xgboost）必须用**同一口径**。
4. 时效（pct、pt）**不参与拟合**（`--drop-decay`，判官标签不看新旧，拟进去只会得到伪相关的权重），但**最终分数保留线上原有的时间衰减**：`最终分 = 拟合出的权威分 × 原衰减系数`，常数沿用 `pct_decay_days=2000`、`pt_decay_days=3000` 与原来的 adc<2 才乘 pt 衰减的规则。第 6 步要同时报告乘与不乘衰减两个数。
5. 不改 `eval.py`、`tools/fit_formula.py` 的评估逻辑；要加功能就加参数，不改口径。

## 第 1 步：把内部数据整理成脚本要的形状

内部数据集和特征的字段名可能和下面不一样。**先弄清内部每一列的含义，再写一个小的转换脚本把它们拼成下面两种文件**，并在报告里写明映射关系。脚本只认下面的格式，不要去改脚本适应内部命名。

**A. 偏序标签 `pairs.tsv`**（train 一份，test 一份，制表符分隔，带表头）

| 列 | 含义 | 来源 |
| --- | --- | --- |
| `url_a` | 第一页的 URL | 内部 pair 里的一侧（例如 pos） |
| `url_b` | 第二页的 URL | 另一侧（例如 neg） |
| `pref` | 判官结论：`a`、`b` 或 `tie` | 判官的最终方向；两次推理相反或都不可比的对**不要写入** |
| `group` | 任意分组标记，没有就填 `all` | 垂类等 |
| `qid` | query 编号，同一 query 的对共用 | 用来按 query 切分与分组 |

要求：train 与 test 的 qid 不能有交集；URL 字符串必须和特征表里的写法完全一致。test 那份放在仓库外（`../npv_ar_private/min_test/pairs.tsv`）。

**B. 每页特征，二选一**

- 原始打分字段：`data/input.tsv`（第 0 列 url、第 5 列 JSON 含 `sr`、`spr`、`adc`、`pcLong`、`pct`、`pt`、`pureTextLen`）加六张表和 `data/meta.json`（`region`、`now`、`tie_band`）。脚本会用 `tools/features_v2.py` 算出全部特征。
- 已有的每页特征表：一个 TSV，首行表头，首列是 `url`，其余全是数值列。用 `--feature-table` 传给脚本。列名随意，但**不能包含**线上 npv 分数、排名位置、pair 编号、判官输出。如果内部表里有这些列，先删掉再用。

**C. 可选 `data/level_map.tsv`**：原始分到 1~1000 等级的阈值表，有它"同档 = 等级差 ≤ 50"才能生效；没有就在 `data/meta.json` 里写 `"tie_band": {"unit": "raw", "value": 0}`。

## 第 2 步：从 train 切一份 dev

按 `qid` 切，20% 作 dev，剩下作 train_fit。中间所有比较用 dev，不碰 test。

```bash
python3 - <<'EOF'

head, body = rows[0], rows[1:]
qids = sorted({l.split('\t')[4].strip() for l in body}); random.Random(7).shuffle(qids)
```

## 第 4 步：按符号和常识修公式

看 `work/fit_v1` 的权重表：

- 脚本列出的"符号与常识相反"的项：`sr`、`spr`、`dr`、`ow`、`adc` 应为正，`is_user_page`、`is_list_page`、`is_ugc_subdomain`、`pc_bit26`、`pc_bit10`、`pc_bit13` 应为负。反了的项多半是在拟合噪声，用 `--drop 项名` 去掉重新拟合。
- 权重绝对值很小（< 0.5）的项直接去掉，不影响一致率就不要。
- 高度共线的项（`sr`、`spr`、`spr_sr` 三个同时在）保留一致率最高的组合，试一下 `--drop sr,spr` 只留 `spr_sr`，看 dev 掉不掉。

## 第 5 步：从树里找非线性（可选，只在 v2 离 0.73 还差 2 个点以上时做）

2. 对重要性前 5 的连续特征画部分依赖（或按分位数分 10 桶看平均预测分）。曲线是台阶的，按台阶边界加 0/1 分档特征；先升后平的，加 `min(x, 阈值)` 截断特征。
3. 看树前两层的分裂组合，若某两个特征反复一起出现（例如 `adc_ge2` 与 `is_list_page`），加一个乘积项。

新特征加进 `tools/features_v2.py` 的 `extra_features`（只用 `x` 的 8 个字段和 URL 字符串，不许读文件），重跑第 3、4 步，记为 **v3**。一次只加一个，dev 不涨的不留。

验收：`eval.py --test` 的 `acc` 与 `work/fit_final` 打印的 test 一致率相同（允许 0.0005 以内的舍入差），输出里有 `form=linear`。记下这个数，记为 **a（不乘衰减）**。

然后加回线上原有的时间衰减，其余乘法项全部关掉（页面类别与正文长度已经是加法项，不能再乘一遍）：

```bash
python3 - <<'EOF'
import json
p = 'sandbox/config.json'; d = json.load(open(p))
d['linear_only'] = False
sc = d['score']
sc['pc_rules'] = []            # 页面类别乘数已拆成加法项
sc['pc_floor'] = 0.0           # 保底分关掉
sc['text_len_rules'] = []      # 正文长度乘数已拆成加法项
sc['adc_bonus'] = {}           # adc 加分已拆成加法项
# pct_decay_days / pt_decay_days / adc_skip_adjust_from 保持原值：这就是线上的衰减规则
json.dump(d, open(p, 'w'), ensure_ascii=False, indent=2)
EOF
python3 eval.py --test    # 输出里应为 form=chain
```

记为 **b（乘衰减）**。b ≤ a 是正常的（标签不看新旧），a − b 就是衰减在权威度上付出的代价：0.3 个点以内照常保留；超过 1 个点要在报告里标出来，供后续决定是否放宽衰减常数或按垂类分开。**最终上线的是 b 这一版**。
