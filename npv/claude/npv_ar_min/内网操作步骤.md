# 内网操作步骤（薄版本，第一阶段：只改参数）

按顺序做，每一步都有"看到什么算通过"。全程只需要 Python 3.8+、git、`codeagent`。

## 第 0 步：把代码带进去

在能上网的机器上下载分支压缩包（GitHub 页面 Code → Download ZIP，分支选 `agent/npv-page-value-score`），拷进内网后解压。需要的只有 `npv/claude/` 下的四个目录，它们必须是同级关系：

```
npv/claude/
  npv_py/        冻结基线
  npv_lab/       评估与拟合工具
  npv_ar/        harness（薄版本复用它的 common.py、metrics.py、score.py）
  npv_ar_min/    薄版本
```

通过标准：

```bash
cd npv/claude/npv_ar_min
python3 --version && git --version && codeagent --version
```

三个都能打印版本号。把 `codeagent --version` 的输出记下来。

## 第 1 步：用合成数据确认工具链

```bash
python3 tools/prepare_synthetic.py
git init -b main && git add -A && git commit -m init
python3 eval.py
python3 eval.py --test
```

通过标准：两行输出，形如 `acc=0.7583 hard=0.5248 ties=0 missing=0 n=2118 ...`。这一步说明 Python 和四个目录的相对位置都对。做完把合成数据清掉：

```bash
rm -rf data labels ../npv_ar_private/min_test .git
```

## 第 2 步：转换标签

把 `labeled_train.jsonl`、`labeled_test.jsonl` 放到 `npv_ar_min/output/`，然后：

```bash
python3 tools/convert_labels.py --train output/labeled_train.jsonl --test output/labeled_test.jsonl \
    --out-train labels/train --out-test ../npv_ar_private/min_test --aux data
```

通过标准：打印 `train: 保留 N 对（有方向 M，query K）`，以及 `data/label_stats.json`。看三个数：

- `strict_acc_同档算半对`：这是线上 npv 在你标签上的现状，也是 agent 要超过的起点；
- `npv_correct_rate_官方口径`：你原来的口径，只作对照；
- `seq_pairs` 里 `pos|neg` 加 `neg|pos` 占总数的比例：这是判官两种顺序结论相反的比例，超过 15% 要先回头看 prompt。

产物：`labels/train/pairs.tsv`（agent 用）、`../npv_ar_private/min_test/pairs.tsv`（人用，仓库外）、`data/urls.txt`、`data/online_npv.tsv`。

## 第 3 步：拉打分字段（最花时间的一步）

拿 `data/urls.txt` 去上游，把每个 URL 的打分输入拉出来，拼成 `data/input.tsv`，格式见 `../输入数据需求清单.md`：

- 制表符分隔，至少 6 列，只读第 0 列（url）、第 2 列（类别标记，可填 1）、第 5 列（JSON）；
- 第 5 列 JSON 必须有 `sr`、`spr`、`pureTextLen`，另有 `adc`（形如 `{"level": N}` 的字符串或空串）、`pcLong`、`pct`、`pt`；
- URL 字符串必须和标签里的一模一样（协议、大小写、尾部斜杠）。

六张表放进 `data/`：`spr.tsv`、`dr_site.tsv`、`dr_suffix.tsv`、`ow.tsv`、`ow_blacklist.txt`、`adc_whitelist.txt`，用线上同一批。

写 `data/meta.json`：

```json
{"region": "zh", "now": 线上打分时的秒级时间戳, "tie_band": {"unit": "raw", "value": 0}}
```

`now` 取线上那次作业的时间基准，衰减要和线上一致。`tie_band` 先用 raw/0，第 4 步做完再改成 level/50。

通过标准，覆盖率检查：

```bash
python3 - <<'EOF'
have = {l.split('\t')[0] for l in open('data/input.tsv', encoding='utf-8') if l.strip()}
need = {l.strip() for l in open('data/urls.txt', encoding='utf-8') if l.strip()}
miss = need - have
print(f"标签 URL {len(need)}，input.tsv 覆盖 {len(need) - len(miss)}，缺 {len(miss)}")
for u in list(miss)[:10]: print("  缺:", u)
EOF
```

缺失率要在 2% 以内。缺的对在评估里算错，缺多了起点就被压低。

## 第 4 步：拟合等级映射（让"分差 ≤ 50 算同档"生效）

两种来源，优先第一种：

**A. 有线上均匀抽样**（同一次作业输出的 url、npv_ori、npv 三列，对参与归一化的页面均匀随机抽，几万行）：

```bash
python3 ../npv_py/fit_level_map.py --sample 线上样本.tsv --out data/level_map.tsv
```

**B. 没有，用标签页面近似**：先用冻结基线给 `data/input.tsv` 打原始分，再和 `online_npv.tsv` 配对：

```bash
python3 ../npv_py/run_npv.py --input data/input.tsv --spr data/spr.tsv --dr-site data/dr_site.tsv \
    --dr-suffix data/dr_suffix.tsv --ow data/ow.tsv --ow-blacklist data/ow_blacklist.txt \
    --adc-whitelist data/adc_whitelist.txt --output data/base_scores --region zh --now $(python3 -c "import json;print(json.load(open('data/meta.json'))['now'])") --scroll 0
python3 - <<'EOF'
ori = {}
for l in open('data/base_scores/npv_ori.tsv', encoding='utf-8'):
    c = l.rstrip('\n').split('\t')
    if len(c) >= 2: ori[c[0]] = c[1]
n = 0
with open('data/level_sample.tsv', 'w', encoding='utf-8') as f:
    for l in open('data/online_npv.tsv', encoding='utf-8'):
        u, lv = l.rstrip('\n').split('\t')
        if u in ori:
            f.write(f"{u}\t{ori[u]}\t{lv}\n"); n += 1
print("配对样本", n)
EOF
python3 ../npv_py/fit_level_map.py --sample data/level_sample.tsv --out data/level_map.tsv
```

B 是近似：标签页面不是均匀抽的，Python 基线和线上 Java 也有细微差别（见 `../与原Java的差异记录.md`）。够用来定同档区间。

然后把 `data/meta.json` 的 `tie_band` 改成 `{"unit": "level", "value": 50}`。

通过标准：`python3 eval.py` 输出里 `unit=level band=50`，`ties` 不再是 0，而且 `acc` 和第 2 步的 `strict_acc_同档算半对` 接近（差 1 到 3 个点正常，因为 Python 基线和线上有差别；差 10 个点以上说明 `now` 或六张表不对）。

## 第 5 步：记基线

```bash
git init -b main && git add -A && git commit -m "baseline"
python3 eval.py
python3 eval.py --test
```

把两行数字抄下来，这是以后所有比较的原点。`labels/` 在仓库里，`data/` 也在（agent 只读，权限里不许改），`../npv_ar_private/` 在仓库外。

## 第 6 步：确认 codeagent 能用、权限生效

先确认它用哪个模型：看 `codeagent` 的配置文件（通常是 `~/.config/opencode/opencode.json` 或项目下的 `opencode.json`）里 provider 和 model 的名字，填到环境变量：

```bash
export OPENCODE_BIN=codeagent
export OPENCODE_MODEL=provider名/模型名     # 不确定就先不设，用它的默认模型
```

三个小测试，都在 `npv_ar_min` 目录下跑：

```bash
codeagent run '只回答一个词：好' < /dev/null                                  # 1. 模型通
codeagent run '运行 python eval.py 并把输出原样贴给我' < /dev/null              # 2. bash 白名单生效
codeagent run '把 sandbox/features.py 第一行改成 # test' < /dev/null; git status --short   # 3. 编辑限制生效
```

通过标准：1 回答"好"；2 贴出 `acc=...` 那一行；3 它说没有权限或做不到，`git status` 为空（features.py 没被改）。

如果第 3 个它真的改了，说明这个版本的 `codeagent` 不读项目目录的 `opencode.json`，或者权限字段写法不同。把 `codeagent --version` 和它的配置文件路径发给我，我改配置。

如果任何一步卡住不退出：加 `--auto` 试一次（它只自动批准没有被明确拒绝的操作，不影响 deny）。还卡就是在等 stdin，确认命令末尾有 `< /dev/null`。

## 第 7 步：有人值守跑第一个会话

```bash
./run_once.sh
```

它会让 agent 读 `program.md`、记基线、连做约 10 次实验。期间另开一个窗口看：

```bash
watch -n 30 'tail -n 5 results.tsv; git log --oneline -5'
```

通过标准：

- `results.tsv` 第一行是 `baseline`，之后每行状态是 `keep`、`discard` 或 `crash`；
- `git log` 里每次 keep 对应一个提交，discard 之后 HEAD 回到之前；
- `journal.md` 每轮有假设和结论；
- `git diff baseline -- sandbox/config.json` 只有数值变化，没有新键、没有 `fit` 被填上。

看到它做了蠢事（反复改同一个数、把 `ties` 刷上去、想绕过去改 `features.py`），记下来，改 `program.md` 的措辞，再跑一个会话。通常要改两三次。

## 第 8 步：无人值守

```bash
nohup ./loop.sh 30 > logs/loop.out 2>&1 &
```

想停就 `touch STOP`。

每天早上三件事：

```bash
python3 eval.py --test            # 它保留的版本在 20% 上到底有没有变好
tail -n 20 results.tsv
git diff baseline -- sandbox/config.json
```

`eval.py --test` 的数字只有人看，不要告诉 agent，也不要据此去改它的 `labels/train`。如果 train 上一路涨、test 不涨，就是在过拟合 train，停下来换 `../npv_ar/` 那套带门槛和 holdout 的版本。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `eval.py` 报 `缺少 data/level_map.tsv` | meta.json 写了 level 但没拟合 | 做第 4 步，或暂时改回 raw/0 |
| `missing` 很大 | input.tsv 没覆盖标签 URL，或 URL 写法不一致 | 回第 3 步看覆盖率检查 |
| `acc` 和 `label_stats.json` 里的现状差很多 | `now` 不对、六张表不是线上那批、或 input 字段缺失 | 对照 `../输入数据需求清单.md` 逐项检查 |
| agent 每轮都 crash | 多半是它写坏了 JSON | 看 `logs/` 里的报错；`program.md` 加一句"改完先 `python3 -c "import json;json.load(open('sandbox/config.json'))"` 检查" |
| agent 一直不调用 eval | 模型在空转 | 缩短 `run_once.sh` 的提示，直接写"现在就跑 python eval.py 记基线" |
