# NPV 特征探索与新特征建议

- 日期：2026-09-14
- 范围：先逐个拆解现有特征到底在测什么、分辨力有多大、哪些对它分不开；再按"能不能马上算、预计能救哪类判错"给出新特征清单；最后给一个筛选特征的流程。
- 依据：代码结构（`npv_py/npv/scorer.py`、`npv_lab/lab/features.py`）、偏序评估方案（真实引擎 top20 头尾抽对，LLM 按来源可信度、专业性、内容质量三维判定）。没有真实数据，所有"占比"类结论来自结构推演，需要用真实数据的诊断报告核实。

---

## 一、现有特征逐个拆解

先把每个特征放到同一张表里看它的"分辨力"，即它能把页面分成多少档、这些档是站点级还是页面级、最多能贡献多少分。

| 特征 | 粒度 | 取值档数 | 最大贡献（分） | 它实际在测什么 | 它分不开什么 |
| --- | --- | --- | --- | --- | --- |
| sr | 站点 | 101 | 54.5（60/1.1） | 站点等级，大概率是流行度或综合质量的站点排名 | 同一站点内的任何两页；大平台的低质页与小站的专业页 |
| spr | 站点 | 连续 | 13.6（60×0.25/1.1） | 站点级第二信号，含义待确认，经分段拉伸后 0.2 到 0.36 区间被放大 4.4 倍 | 同上；且与 sr 大概率高度相关，信息冗余 |
| dr | 站点或后缀 | 3 | 12 | 域名类型等级，站点表优先、后缀表兜底 | 同一类型内的站点；后缀表命中的站点一律同分 |
| ow | 站点 | 2 | 4 | 是否官网：区域白名单后缀、黑名单、官网表 | 官网内部页面之间；"官网"但内容差的页 |
| adc | 站点 | 4 | 15，且 ≥2 时免除页面级降权 | 上游给的权威等级，外加 URL 子串白名单 | 权威站点内部的列表页与正文页（被免除降权后完全同分） |
| pc 位 | 页面 | 14 位但只取第一个命中 | 乘 0.6 到 0.9，或保底 60 | 上游的页面类型分类 | 同时命中多位的页只吃一次；各位含义无文档 |
| pct 衰减 | 页面 | 连续 | 乘 0.28 到 1 | 页面时间距今的 sigmoid | 它测的是新旧，不是权威；常青内容被误伤 |
| pt 衰减 | 页面 | 连续 | 乘 0.46 到 1 | 同上，仅 adc<2 | 同上 |
| pureTextLen | 页面 | 3 | 乘 0.8 或 0.9 | 正文长度两档阈值 | 300 字以上的所有页面；长的列表页与长的正文页 |

三个结构性结论：

**1. 这是一个站点先验，页面级只有修饰作用。** 基础分 76 分里 70.5 分来自 sr 和 spr，全部是站点级。页面级只剩乘法系数和正文长度。同一站点两页的分差上限约为基础分的 40%，而且只由页面类型位和时间决定。前 20 名里同站或同级站点的对，模型基本靠掷硬币。

**2. 权威站点的页面级信号被主动关掉了。** adc ≥ 2 跳过页面类别和 pt 衰减，意思是 gov、edu 或白名单站点的列表页、搜索页、用户页与正文页同分。LLM 看到 gov 站的一个栏目列表页和一篇正式公告，会判后者更权威；npv 判不出来。

**3. 时间衰减在测另一个东西。** 评估 rubric 明确让 LLM 忽略新旧，而 npv 里衰减最多能把分数打到 0.28 倍，权重远超任何页面级特征。fresh 对 stale 的对，只要权威相当，npv 就系统性判错。这不是特征缺失，是把两个目标揉进了一个分数。

另外几个"特征层面的 bug"，不改也会持续制造判错：

- 官网白名单 `endsWith` 无域名边界，`xbaike.baidu.com` 也命中 `baike.baidu.com`；`.edu.com` 疑为 `.edu.cn` 笔误。
- adc 白名单在整个 URL 上做子串匹配，查询参数里出现白名单串的页也被判为权威。
- `news` 子串规则在整个 URL 上匹配，`newsletter`、站名含 news 的都被降权。
- 保底 60 发生在正文长度系数之前，可以被打穿。
- dr 后缀表多重命中时取哪个取决于 HashMap 顺序。

## 二、判错的对会长什么样

新特征的价值只能用"它能救哪一类判错"来衡量，所以先把前 20 名头尾对可能的判错分成五类。拿到真实标签后用分维度分数核对各类占比，占比决定投入顺序。

| 类型 | 形态 | 现有特征为什么分不开 | 需要的信号 |
| --- | --- | --- | --- |
| A 跨层级 | 政务或机构站对小博客 | 一般能分开，sr、dr、ow 都在起作用 | 现有特征够用，主要是权重 |
| B 同站或同级 | 同一平台的两页；两个同等级站点各一页 | 站点特征完全相同或几乎相同 | 页面级：页面类型、内容质量、来源标识 |
| C 大平台低质页对小站专业页 | 知乎、贴吧、CSDN 上的灌水内容对某医院、某高校、某协会官网的正式内容 | sr 把平台的权威继承给了每一页；小站 sr 低、不在任何白名单 | 站点级"机构身份"信号；页面级"内容专业性"信号；UGC 平台的页面应少继承站点权威 |
| D 页面类型 | 列表页、标签页、用户主页对正文页 | pc 位只取第一个命中，adc≥2 时干脆不看 | URL 形态、页面结构 |
| E 新旧 | 同一权威的新页对旧页 | 衰减压低旧页，而 LLM 不看新旧 | 把衰减从权威分里拆出去 |

经验判断：A 类占比高说明标注的对太容易，应换抽样方式；真正决定分数上限的是 B 和 C。

## 三、新特征建议

按"现在就能算"到"要建新数据源"分四层。每条给出定义、救哪类判错、成本、风险。

### 第 0 层：把现有信号拆开、放平（零成本，先做）

这一层不引入新信息，只是把手工合成和手工阈值拆成独立特征，交给拟合定权重。收益是"权重能被数据定"，也是后面所有特征的基础。

| 特征 | 定义 | 救什么 |
| --- | --- | --- |
| `sr_raw`、`spr_raw` | 各自归一化后直接作为两个特征，不再合成 spr_sr | 让拟合决定 spr 是否有增量信息，替代那段拍出来的分段映射 |
| `sr_missing`、`spr_zero`、`pct_missing`、`pt_missing` | 缺失指示 | 缺失兜底值（0.25、不衰减）由数据定 |
| `pc_bit10` 到 `pc_bit38` | 14 位各一个 0/1，已在 features.py | D 类；同时命中多位的页能叠加 |
| `adc_1`、`adc_2`、`adc_3`、`adc_whitelist_hit` | adc 等级 one-hot，白名单命中单独一位 | 让"跳过页面级调整"这个硬规则变成可拟合的项 |
| `dr_from_site`、`dr_from_suffix`、`dr_value` | dr 的来源与数值分开 | 后缀兜底与站点表精确命中的可信度不同 |
| `ow_region`、`ow_black`、`ow_table` | ow 的三个来源分开 | 三者可信度不同 |
| `log_decay_pct`、`log_decay_pt` | 衰减系数取对数作为特征 | E 类：权重可以被拟合压到接近 0，等价于把新旧从权威里拆出去 |
| `text_len_log` | 正文长度对数，已在 features.py | 替代两档阈值 |

做完这一层，打分公式变成纯线性：分数 = 权重点乘特征。`fit_weights.py` 才能把整套公式一次拟合，而不是只拟合基础分那层。

### 第 1 层：URL 形态（零成本，只要 url）

URL 是唯一已经在手、又携带页面级信息的输入。这些特征专治 D 类，也能部分识别 C 类里的 UGC 页面。

| 特征 | 定义 | 说明 |
| --- | --- | --- |
| `url_depth` | 路径段数，已有 | 首页与深层页 |
| `is_homepage` | 路径为空或 index | 首页通常是站点身份页 |
| `path_kind_*` | 路径含 `list`、`tag`、`search`、`category`、`page=`、`sort=` 等 → 列表类；含 `u/`、`user/`、`space/`、`people/`、`member/`、`author/` → 用户主页；含 `forum`、`thread`、`bbs`、`post`、`reply` → 论坛；含 `video`、`album`、`download`、`app` → 资源页 | 每类一个 0/1；与 pc 位互为补充，pc 位含义未知时这是可解释的替身 |
| `subdomain_kind_*` | 主机第一段为 `bbs`、`blog`、`tieba`、`zhidao`、`wenku`、`jingyan`、`m`、`news`、`www` 等 | **识别 UGC 子域**是 C 类的关键：同一 sr 的站点，`zhidao.` 与 `baike.` 的页面质量分布完全不同 |
| `is_root_host` | 主机就是注册域（无子域或仅 www） | 主站页比子站页更可能是机构自己发布的 |
| `has_query_string`、`query_param_count` | 有无 `?` 及参数数 | 动态列表页、追踪参数 |
| `last_segment_numeric_id` | 末段是纯数字或 `\d+\.html` | 典型的内容页 id 形态，与列表页区分 |
| `path_has_date` | 路径含 `20\d{2}/\d{2}` 或 `20\d{6}` | 新闻稿、公告的常见形态 |
| `url_len_log` | URL 长度 | 过长常见于聚合、追踪页 |
| `is_https` | 协议 | 弱信任信号 |
| `ext_kind` | `.html`、`.shtml`、`.php`、`.aspx`、`.jsp`、无扩展 | 与站点技术栈相关，弱 |

风险：这些是启发式，某些站点的 URL 规则会反着来；靠拟合定权重，不要手工给系数。

### 第 2 层：页面内容线索（需要正文与标题，上游已有抽取能力）

LLM 判"来源可信度"和"专业性"看的正是这些东西。它们是 B 类和 C 类的主要解药，也是 rubric 三个维度在特征侧的直接对应。上游既然能算 pureTextLen，就有正文抽取，在同一处顺手算即可。

来源标识（对应 source_credibility）：

| 特征 | 定义 |
| --- | --- |
| `has_byline` | 正文含"作者：""记者""编辑：""来源："等署名模式 |
| `has_org_signature` | 尾部含机构落款、"版权所有""地址""电话""备案号" |
| `has_pub_date` | 有可解析的发布日期 |
| `has_contact_or_about` | 含"联系我们""关于我们" |
| `has_disclaimer` | 含"免责声明""本文仅代表" |

专业性（对应 expertise）：

| 特征 | 定义 |
| --- | --- |
| `has_references` | 含"参考文献""引用""来源：""据……报道"，或尾部有编号列表 |
| `numeric_density` | 数字、单位、百分号占比，数据密集的内容更像专业内容 |
| `outlink_ext_count_log` | 外链数，引用外部来源 |
| `avg_sentence_len`、`long_para_ratio` | 论述型内容的句段形态 |
| `title_body_overlap` | 标题词在正文出现的比例，低说明标题党或聚合页 |

内容质量（对应 content_quality）：

| 特征 | 定义 |
| --- | --- |
| `text_html_ratio` | 纯文本占 HTML 字节比，模板重的页低 |
| `link_text_ratio` | 锚文本占正文比，列表页、导航页高 |
| `boilerplate_ratio` | 与本站其他页重复的文本比例，需要站内去重 |
| `ad_keyword_density` | "加微信""扫码""下载 App""免费领取""咨询热线"等营销词密度 |
| `para_count_log`、`heading_count`、`table_count`、`image_count` | 结构完整性 |
| `stopword_ratio` | 学术上验证过的可读性代理 |
| `title_seo_pattern` | 标题含多个 `_`、`-`、`|` 分隔的关键词堆砌 |

这一层的每个特征都便宜，但要在全量页面上算才能上线，所以要进上游抽取流程。建议先在标注的几千页上算出来做筛选，确认有增益的再推全量。

### 第 3 层：站点级新表（需要建数据源，投入中等，收益最大）

C 类判错的根子是"站点权威只有一种来源，就是流行度"。要补的是流行度之外的站点身份与信任信号。

| 特征 | 定义 | 怎么来 | 为什么值得 |
| --- | --- | --- | --- |
| `icp_entity_type` | 备案主体性质：政府、事业单位、企业、社会团体、个人、无 | ICP 备案库，按注册域查 | 中文站最强的身份信号，直接对应"来源可信度"；某县医院、某行业协会官网 sr 很低，但备案主体是事业单位 |
| `site_llm_grade` | 站点级权威档位 0 到 4 | 对几千个站点用 LLM 看首页加"关于"页各判一次，建一张表 | 用几千次调用换一个不依赖流行度的站点先验，是最便宜的"新信息源"；抽样要分层覆盖长尾 |
| `site_ugc_flag` | 站点或子域是否以用户生成内容为主 | 人工维护几百条加规则 | C 类核心：与 sr 做交互项 `sr × (1 − ugc)`，让 UGC 平台的页少继承站点权威 |
| `site_focus` | 站点主题集中度：站内页面主题分布的熵 | 需要页面主题分类 | 主题集中的站更可能是专业来源，对应"topical authority"；与页面主题一致时加成 |
| `site_page_count_log` | 站点收录页数 | 索引统计 | 与 sr 互补：大而杂对小而专 |
| `site_age_days_log` | 域名或站点首次收录时间 | whois 或索引 | 弱但稳定的信任先验 |
| `site_has_baike_entry` | 站点或其主体有百科词条 | 百科表 | 机构知名度的非流行度代理 |
| `site_inlink_domains_log` | 入链来源域名数 | 链接图 | 如果 sr、spr 之一不是链接信号，这是 pr 停产后页面级链接信号的站点级替代 |
| `site_penalty_flag` | 垃圾、采集、作弊标记 | 反作弊系统 | 负向信任，目前只有一张官网黑名单 |

### 第 4 层：行为信号（有数据但要谨慎）

| 特征 | 定义 | 风险 |
| --- | --- | --- |
| `site_ctr_debiased` | 站点级按位置去偏的点击率 | 流行度而非权威；与 sr 冗余；引入反馈回路 |
| `page_dwell_median` | 页面停留时长中位数 | 长文天然高 |
| `page_click_share_in_query` | 同 query 下的点击份额 | 依赖当前排序 |

建议只作为对照：加进去看遮域名那一轮的一致率是否也涨。只在带域名那一轮涨，说明它在学品牌，不是权威。

### 中期：蒸馏一个页面质量模型

LLM 判一页要几秒、几分钱，全量不可能；但用 LLM 给两三万页打 `authority_grade`，训练一个小文本分类器（标题加正文前 512 字）预测档位，就能给全量页面一个 `page_quality_pred` 特征。这是"LLM 做标注、小模型做打分"的标准路线，也是把 rubric 三个维度真正搬进 npv 的办法。注意两点：训练集与评估集的页面不能重叠；评估时看遮域名那一轮和人工复核集，避免"LLM 评 LLM"的循环。

## 四、结构上的两个建议

**1. 把新旧拆出去。** 输出两个量：`npv_authority`（不含衰减）和 `freshness`（衰减系数），由下游排序器决定怎么合。理由在第一节第 3 条。如果下游暂时只能接一个分数，至少让衰减常数按垂类分开：新闻类保留，百科、法规、教程、机构介绍类放缓到 5000 天以上。

**2. 改成单一线性形式。** 第 0 层做完后，分数 = Σ 权重 × 特征，可以加少量交互项（`sr × ugc`、`sr × is_user_page`）。权重全部由 pairwise 逻辑回归定，不再有乘法链、保底和加分这些拍出来的结构。可解释性不损失，每项贡献照样能打印。

## 五、怎么筛选一个候选特征

每个候选都过同一套关卡，避免凭感觉加：

1. **覆盖率**：在全量样本上非缺失、非常数的比例。低于 5% 的先放一边。
2. **单变量一致率**：只用这个特征的高低去判偏序对，与 LLM 标签的一致率；50% 附近的没有单独信息，但仍可能有交互价值。
3. **冗余**：与现有特征的秩相关；与 sr 相关超过 0.8 的，增量很可能为零。
4. **增量**：加进 `features.py` 并纳入 `fit_weights.py` 拟合，验证集一致率、小分差桶一致率、误压率三个数与不加时比。只有验证集显著提升才保留。
5. **两轮对照**：带域名与遮域名两轮的提升是否同向。只在带域名那轮涨的特征是在学品牌。
6. **可上线**：全量页面能否在打分时算出来。只在标注集上有的特征不能进模型。

这套关卡可以做成一个 `feature_screen.py`，输入打分输出的特征 JSON 和标签，一次性给出每个特征的覆盖率、单变量一致率、与 sr 的相关、拟合增量。

## 六、建议的投入顺序

| 顺序 | 内容 | 成本 | 预计救的判错 |
| --- | --- | --- | --- |
| 1 | 第 0 层拆平 + 全线性拟合 | 一两天，无新数据 | 权重层面的全部收益；衰减误伤（E） |
| 2 | 第 1 层 URL 特征 | 半天 | D 类，部分 C 类 |
| 3 | `site_ugc_flag` 与 `sr × ugc` 交互 | 一天维护名单 | C 类中最大的一块 |
| 4 | 第 2 层内容线索，先在标注集上筛，再进上游 | 一周 | B 类、C 类 |
| 5 | `icp_entity_type`、`site_llm_grade` | 一两周，建两张表 | C 类中长尾机构站 |
| 6 | 拆出 freshness | 视下游 | E 类 |
| 7 | 蒸馏页面质量模型 | 一个月 | B、C 类的剩余部分 |
| 8 | 行为信号 | 有数据即可 | 待验证 |

前三步不需要任何新数据源，拿到第一批标签就能开始。

```python
RESOURCE_PAT = re.compile(r"/(video|album|download|app|apk|music|mp3)(/|\.|$)")

def url_features(url, site):
    u = url if "://" in url else "http://" + url
    p = urlparse(u)
    path, query = p.path or "/", p.query
    segs = [s for s in path.split("/") if s]
    labels = site.split(".")
    sub = labels[0] if len(labels) > 2 else ""
    last = segs[-1] if segs else ""
    return {
        "is_homepage": float(not segs or last.lower().startswith("index")),
        "path_list": float(bool(LIST_PAT.search(path + "?" + query))),
        "path_user": float(bool(USER_PAT.search(path))),
        "path_forum": float(bool(FORUM_PAT.search(path))),
        "path_resource": float(bool(RESOURCE_PAT.search(path))),
        "sub_ugc": float(sub in UGC_SUBDOMAINS),
        "sub_www_or_none": float(sub in ("", "www")),
        "has_query": float(bool(query)),
        "query_params": min(len(query.split("&")) if query else 0, 5) / 5.0,
        "last_numeric_id": float(bool(re.fullmatch(r"\d+(\.s?html?)?", last))),
        "path_has_date": float(bool(re.search(r"20\d{2}[-/]?\d{2}", path))),
        "url_len_log": math.log1p(len(url)) / math.log1p(500),
        "is_https": float(p.scheme == "https"),
    }
```

加进 `extra_features` 后默认权重为 0，不影响基线；用 `fit_weights.py --features ...` 纳入拟合即可。
