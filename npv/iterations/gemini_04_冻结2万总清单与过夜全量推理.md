## Part A：下班前一次性生成并冻结 20,000 对总清单与离线快照包

### A1. 站点切分与页面清洗（基于 6,600 host / 23,228 页池）
1. **站点口径**：严格按 **`host`（完整子域名）** 分组，每个 `host` 的 `sr` 取其常量值。
2. **页面清洗（严禁滤掉列表/导航/聚合页！）**：
   - 仅剔除正文 `< 50` 字符的空页/抓取失败页（单独记录剔除数）；
   - 同一 `host` 内标题相同或正文哈希完全相同的重复页只留 1 页；
   - 不同 `host` 之间正文完全相同的转载页不互配成一对。
3. **按 `host` 哈希 6:2:2 切分**（所有配对只在各自划分内部进行，**跨划分对子必须严格为 0**）：
   ```python
   # 确定性哈希，后续追加新 host 不打乱已有划分
   h = int(hashlib.md5(("npv:" + host).encode("utf-8")).hexdigest()[:8], 16) / 0xFFFFFFFF
   split = "train" if h < 0.6 else ("dev" if h < 0.8 else "test")
   ```
   检查三份划分的 `host` 数比例接近 `6:2:2`，且 20 个 `sr` 层在三份中的分布大致均衡。

### A2. 20,000 对主清单构成（40% 站内 + 60% 跨站）

1. **站内对 `in_site`：共 8,000 对（40%）**
   - 每页在站内对中最多使用 **1 次**，单站最多配 `floor(n / 2)` 对。
   - 配额优先级：**优先全额保留全部 600 个 10 页大站的 3,000 对**（大站内部差异最丰富），其余 2~4 页普通站按比例均匀抽齐 **5,000 对**，合计 8,000 对（按各划分实际占比自动落入 train ≈4,800 / dev ≈1,600 / test ≈1,600）。
   - **配对策略（训练与评测区别对待）**：
     - **`dev` / `test` 站点**：站内页面**纯随机配对**（保证评测无偏）；
     - **`train` 站点**：**高信息量对比配对**——4 页以内选总差异（`|log(len_a/len_b)| + 1[url首段或pc不同]`）最大的配对法；10 页大站按正文长度排序后短半段配长半段，并优先让不同一级路径/栏目或不同页面类别互配。

2. **跨站对 `cross_random`：共 12,000 对（60%）**
   - 仅在同一 `split` 内配对；同一对 `(host_a, host_b)` 最多配 **1 次**；每页在跨站对里最多使用 **2 次**（跨全清单每页总复用 ≤3 次）。
   - **单站跨站名额封顶**：`quota(n) = min(2 * n, 5)`（防止 600 个大站垄断站点级权重；若名额富余，优先满足 4 档 `sr` 差配比并让所有站点均匀轮流使用）。
   - **4 档 `sr` 差目标配比**（左开右闭，首档含 0）：
     - `<=10`：**30%**（3,600 对，Batch 1 占 900 对）
     - `10~30`：**45%**（5,400 对，Batch 1 占 1,350 对）
     - `30~50`：**15%**（1,800 对，Batch 1 占 450 对）
     - `>50`：**10%**（1,200 对，Batch 1 占 300 对）
   - 每对的 `A / B` 初始先后顺序随机定（`seed=42`）。

3. **外挂痛点监测切片（额外 ~200 对，不混入 20,000 主集统计）**：
   - `slice_ad_soft`（100 对，高分站 `sr>=70` 软文/推广嫌疑页 vs 普通页）+ `slice_cross_gov`（约 50~100 对，按 `gemini_02` 精准规则捞取的真跨界政务页 vs 同领域专业页，不足 100 对有多少算多少）；
   - 标记 `purpose=slice`、`batch=0`（最优先跑完，仅 ~400 次调用），同样记录所属 `host` 划分。

### A3. 分层赋予 `batch` 序号（关键：让过夜中途任何时刻停下都立即可用）

对 20,000 对主清单按 `(split, type, sr_gap_bucket)` 分层随机编号，分配执行批次：
- **`batch = 1`**：25% = **5,000 对**（`train 3,000 / dev 1,000 / test 1,000`；站内 2,000 + 跨站 3,000）
- **`batch = 2`**：25% = **5,000 对**（累计 10,000 对）
- **`batch = 3`**：50% = **10,000 对**（累计 20,000 对）

**执行顺序严格按 `batch = 0 (切片 ~200 对) → batch = 1 (5,000 对) → batch = 2 (5,000 对) → batch = 3 (10,000 对)` 依次推理！**
这样哪怕回家过夜只跑完 10,000 对或 14,000 对，前 5,000 对（Batch 1）或前 10,000 对（Batch 1+2）都已经是完整无偏的微缩基准集，次日立刻可以开工拟合，不用等全部 2 万对跑完。

### A4. 下班前打包冻结以下 4 个离线文件（带回家只需连模型 API，不依赖内网查库）

全部存放在 `prod_20k/` 目录并做完整性校验：
1. **`master_20k_pairs.tsv`**：列 `pair_id, batch, split, type, purpose, sr_gap_bucket, url_a, url_b, host_a, host_b, sr_a, sr_b, len_a, len_b`（按 `batch` 升序排列）。
2. **`master_20k_pages_snapshot.jsonl`**：覆盖总清单中所有去重 URL 的完整离线快照，每行包含：
   - 推理必需字段：`url, host, title, date, body_truncated`（提前按 3,000+500 截断好，减小体积便于带走）；
   - 拟合必需原始字段：`sr, spr, dr, ow, adc, pcLong, pct, pt, pureTextLen, online_npv`（及池子中其他已有基础列，确保后续拟合和特征工程直接从快照重算，不产生时间漂移）。
3. **`prompt_v2_1_1_final.json`**：冻结的 `v2.1.1-final` System + User Prompt。
4. **`manifest_check.json`**：自动验收清单（必须全通过再启动推理）：
   - 主集总数 = 20,000（±1% 允许）；站内 ≈ 8,000、跨站 ≈ 12,000；
   - `train : dev : test` ≈ 6:2:2，**跨划分对子 = 0**；
   - 同一 `(host_a, host_b)` 跨站重复 = 0；每页站内使用 ≤ 1、跨站使用 ≤ 2；
   - `master_20k_pages_snapshot.jsonl` 对清单 URL 的覆盖率 = **100%**（缺失 0）；
   - Batch 1 / 2 / 3 各批内部的 `split`、`type`、`sr_gap_bucket` 比例一致。

## Part B：过夜高可靠推理脚本要求（防断网 / 防限流 / 防休眠）

请编写 `prod_20k/run_batch_infer.py`（支持 `--workers 20`、`--max-batch 3`、`--resume`），必须满足以下 6 条工程保险：

1. **逐条即时落盘 + 断点续跑**：
   - 结果追加写入 `prod_20k/raw_labels_hydrogen_v2_1_1.jsonl`（每行一个 `(pair_id, order)` 的完整结果，含原始 parsed JSON、时间戳、耗时、模型名、`prompt_version`），每写一条立即 `flush()`（加线程锁防并发写乱）；
   - 启动时扫描已有 `jsonl` 中 `status == "ok"` 的 `(pair_id, order)` 集合，自动跳过已完成项；失败项自动重跑。
2. **绝不因单次网络抖动崩溃**：
   - 捕获超时、连接断开、HTTP 429/5xx、空响应、JSON 解析异常；
   - 指数退避重试（如 `2s → 6s → 18s`，单条最多重试 3 次）；若全部 3 次仍失败，写入 `status="api_error"` 或 `parse_error` 日志后继续跑下一条，**禁止抛未捕获异常终止主进程**；
   - 若连续出现 ≥10 次网关报错，自动暂停冷却 `60s` 再恢复（防网关瞬时过载打死）。
3. **严格按 `batch=0 → 1 → 2 → 3` 顺序调度**：优先把 Batch 0 和 Batch 1（5,000 对）打完落袋，再进 Batch 2、Batch 3。
4. **进度与 ETA 监控**：每完成 100 次调用打印一行摘要（当前 batch、已完成/总数、实时速度 calls/min、失败率、预估剩余时间），同时每完成一个完整 Batch 自动触发一次阶段汇总脚本，写出 `summary_batch{k}.json`。
5. **并发建议**：默认 `--workers 20`（参考 `gemini-4-hydrogen` 均值 ~25.8s/次：20 并发约 46 次/分钟 ≈ 2,760 次/小时，**5,000 对/1 万次约 3.6 小时，10,000 对/2 万次约 7.2 小时，20,000 对/4 万次约 14.5 小时**；如网关稳定可按需调到 25~30）。
6. **防休眠提醒**：在启动命令示例里提醒 macOS 使用 `caffeinate -dimsu python3 prod_20k/run_batch_infer.py ...` 防止电脑息屏休眠断流；并先用 `--limit 20` 在公司测通 20 次调用（约 1 分钟）确认无报错再带回家开跑！
