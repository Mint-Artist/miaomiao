# 结构切分规则：业界与开源框架对照

本文核对开源框架和云厂商在"按结构切分"时用的具体规则和默认参数，并与我们 md_struct / html_struct 的规则逐项对照，用于决定下一步要调整、要做实验的参数。

- 开源框架的规则来自 GitHub 源码；云厂商的规则来自官方文档。读取日期均为 2026-11-13，各来源的版本见文末。
- 标注"推断"的是从代码逻辑推出、未实际运行的结论；"未公开"指官方文档中找不到。

## 一、结论

1. **按标题分节、节内再按长度切，是各家的共同做法。** 我们"标题处断开、标题挂到下一段"的规则与主流一致。
2. **标题路径拼进向量化文本是常见做法，而我们目前没有做。** Docling、Google、百度千帆、阿里百炼、RAGFlow（laws 模板）都会把祖先标题拼到用于向量化的文本里。我们已有 `_ctx` 版本，但不在本轮评测范围内，应列为下一组实验。
3. **短块合并是常见做法。** 火山引擎默认合并，Unstructured、Haystack、Chonkie、RAGFlow 都有类似规则。我们新增的 `_merge` 方法方向正确。各家的分歧在于是否允许跨标题合并。
4. **块长普遍比我们大。** 各家默认多在 300–600 个单位（token 或字），我们是软上限 256 字、硬上限 512 字。
5. **表格的主流做法是：小表整表成块，大表按行切并重复表头。** 我们目前不论大小都按 256 字切。
6. **中文处理普遍较弱。** LangChain、Unstructured 的默认分隔符没有中文标点，Dify 的 HTML 处理会丢掉全部结构，RAGFlow 处理 HTML 时会跨标题打包。我们在这些方面的规则比多数默认配置更细。

## 二、逐项对照

| 维度 | 我们（md_struct / html_struct） | 业界做法 | 判断 |
|---|---|---|---|
| 节边界 | 遇到标题断开，标题挂到下一段开头 | Google：一个块只来自一个布局实体；AWS：不跨页和节合并；Docling HybridChunker：只合并标题路径完全相同的块；Haystack、Dify 的 Markdown 处理：不跨标题 | 一致 |
| 跨标题合并 | 不跨（`_merge` 只合并不足 20 字的块） | Unstructured 默认会跨标题合并小节（`combine_text_under_n_chars` 默认等于 `max_characters`）；RAGFlow manual 模板会无条件合并不足 32 token 的块 | 我们更严格，合理 |
| 内容类型分组 | 正文、列表、同一张表各自打包 | Google 把列表视为一个布局实体；Docling 整个列表一块；Unstructured 表格独占一块 | 一致 |
| 块长 | 软上限 256 字，512 字以内的段落不拆 | Google 500 token（可选 100–500）；AWS 约 300 token；Docling 256 token；Unstructured 500 字符；Azure Content Understanding 500；阿里控制台 600 token、API 500；火山 500；千帆 1200 字；Dify 500 / 1024 字符 | 偏小，值得做对照实验 |
| 短块 | 原版：不足 20 字丢弃；`_merge`：并入相邻块 | 火山 `merge_small_chunks` 默认开启；Haystack Markdown：只有标题、没有内容的部分并入后一块；Haystack DocumentSplitter：碎块并入前一块；Chonkie：最小 24 字节，就近合并 | `_merge` 与主流一致 |
| 超长段落 | 按 。！？；… 和换行分句，再在逗号或顿号处切 | LangChain、Unstructured 默认分隔符不含中文标点，会按字符硬切；LlamaIndex 只认 。？！；RAGFlow 认 `\n!?;。；！？`；Azure 设为 zh-Hans 后按句切 | 我们更细 |
| 表格 | 按行打包到 256 字，每块重复表头 | Unstructured：整表不超过上限时整表成块，超长按行切并重复表头；Chonkie：每 3 行一块，带表头；腾讯：按行切，带表头；千帆：一行一块；AWS：检索命中后返回整表（不超过 1 万字符时）；Google：表格和表格说明放同一块 | 可改为"小表整表成块" |
| 标题上下文 | 只在每节第一块里带本级标题；没有祖先路径 | 拼进向量化文本：Docling `contextualize()`、Google `includeAncestorHeadings`、千帆"关联标题"、阿里返回的 text 带标题、RAGFlow laws 模板。只放元数据：Azure、LangChain、阿里 `hier_title`、火山 `chunk_title` | **缺失，应优先实验** |
| 重叠 | 无 | 按结构切分时多数不用重叠：Azure semantic 模式禁止、阿里按标题切时不支持、Docling 和 Unstructured 默认 0 | 一致 |
| 伪标题识别 | 整行加粗、不超过 40 字、末尾无标点 | RAGFlow 中文规则：不少于 32 字且无空格、或含 ，。；！ 的行不算标题；LangChain HTMLSectionSplitter：字号大于 20px 视为标题 | 可补"行内含句读标点则不算标题" |
| HTML 噪声 | 依赖 EC 已抽取正文 | Google 可按标签、class、id 排除（示例排除 header、footer、nav、aside）；千帆支持 CSS 选择器筛选 | 由 EC 负责，暂不需要 |

## 三、各来源的关键规则

### 开源框架

| 框架 | 结构边界 | 大小（默认） | 短块 | 表格 | 标题上下文 |
|---|---|---|---|---|---|
| LangChain MarkdownHeaderTextSplitter | 按指定标题级别切，不跨标题 | 无大小控制 | 无 | 无 | 元数据（默认不进正文） |
| LangChain HTMLSemanticPreservingSplitter | 按标题分组，可保留指定元素 | 1000 字符，软上限，保留元素可超限 | 无 | 保留时子节点用空格拼接，行列结构丢失 | 只有当前一级标题 |
| LangChain RecursiveCharacterTextSplitter | 分隔符递归 | 4000 字符 / 重叠 200 | 无 | 无 | 无 |
| LlamaIndex MarkdownNodeParser | 每个标题开新节 | 无 | 无 | 无 | `header_path`，不含当前标题 |
| LlamaIndex HTMLNodeParser | 同名标签连续合并，标签变化就切 | 无 | 无 | 默认不抽取 table | 只记录标签名 |
| LlamaIndex SentenceSplitter | 段落 → 句子 → 正则 | 1024 token，硬上限，重叠 200 | 无 | 无 | 无 |
| Haystack MarkdownHeaderSplitter | 按标题切，可选节内二次切分 | 无，二次切分默认 200 词 | 只有标题、没有内容的部分并入后一块 | 无 | `header` + `parent_headers` |
| Chonkie RecursiveChunker | 段落 → 句子 → 停顿 → 空格 → 硬切 | 2048 字符 | 最小 24 字节，就近合并 | 无 | 无，会跨标题合并 |
| Chonkie TableChunker | — | 每块 3 行 | — | 每块重复表头 | — |
| Unstructured `chunk_by_title` | 遇到 Title 开新块 | 500 字符硬上限，软上限默认相同 | 前一块不足阈值时吸收后一块，**默认可跨 Title** | 独占一块；超长时按行切，重复表头 | Title 作为块正文第一行 |
| Docling HybridChunker | 按文档元素，只合并标题路径相同的相邻块 | 256 token（默认英文 MiniLM 分词器） | `merge_peers`，不跨标题 | 整表一块；超长按行切（推断：默认序列化器下表头重复不生效） | 完整祖先路径，只拼进向量化文本 |
| RAGFlow naive（HTML） | h1–h6 改写成 `#`，但按 token 贪心打包，**跨标题** | 512 token（API 默认），无硬上限 | 贪心合并 | 整表抽出放到末尾，**脱离原阅读顺序** | `#` 前缀 |
| RAGFlow laws 模板 | 标题树，深度 2 | 512 token | — | — | 每块前拼祖先标题路径 |
| Dify | Markdown 按 `#` 切；HTML 用 `get_text()` 压平 | 500 / 1024 字符（参数名叫 token，实际按字符计） | 自定义模式下不合并 | 无 | 只有本级标题 |

## 四、建议的对照实验

每组只改一个变量，其余规则保持不变。

| 优先级 | 实验 | 变化 | 依据 | 成本 |
|---|---|---|---|---|
| 1 | 标题路径前缀 | 启用现成的 `md_struct_ctx` / `html_struct_ctx`：块前加祖先标题路径（不超过 100 字） | 多家采用；我们之前的实验里这是唯一稳定提升召回的做法 | 只需切分和推理，无需写代码 |
| 2 | 短块合并 | `_merge`：不足 20 字的块并入相邻块 | 火山默认开启；多家框架有类似规则 | 代码已完成 |
| 3 | 块长 | 软上限 256 → 384 / 512 | 各家默认多在 300–600 | 改参数即可；同时看固定条数和固定字数两类指标 |
| 4 | 小表整表成块 | 不超过 512 字的表格整表成块，超长才按行切 | Unstructured、Google | 改动小 |
| 5 | 伪标题收紧 | 行内含 ，。；！ 的加粗行不算标题 | RAGFlow 中文规则 | 改动小，影响面小 |

不建议采用的做法：
- **跨标题合并小节**（Unstructured 默认）：会破坏结构边界，与我们要证明的方向相反。
- **表格移到正文末尾**（RAGFlow 的 HTML 处理）：打乱阅读顺序。
