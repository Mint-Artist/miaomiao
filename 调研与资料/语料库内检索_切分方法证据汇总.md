# 语料库内检索：切分方法的实验证据汇总

## 说明

**语料库内检索**：在整个语料库里检索文本块，把块映射回所属文档，判断找到的文档是否相关。我们的召回评测（块 → 网页 url → 精排前 10 的网页）属于这一类。

**文档内检索**：在单篇长文档里定位证据段落。这一类结论与语料库内检索经常相反（见第 1 节），本文只作对照，不作主要依据。

方法分类沿用本项目口径：
- **机械切分**：定长 token / 字符 / 句数；
- **结构切分**：段落、标题、版面元素、HTML 结构；
- **语义切分**：相邻句向量断点、语义聚类、LLM 定边界、命题分解。

数值均照录原文；"pts"为百分点差，由本文按原文数值计算。

## 1. Zhou 等，SIGIR 2026（最对口）

**设置**：
- 语料：BEIR 的 FiQA、ArguAna、SciDocs、TREC-COVID、SciFact、NFCorpus。
- 文档得分取文档内最高分的块（MaxP），指标 nDCG@10。
- 四个向量模型，配对 t 检验（p < 0.05）。
- 这里的"段落"是按换行切，不是 HTML 结构。

**表 3，各方法平均 nDCG@10（语料库内，先切分再嵌入）**

| 方法 | Jina-v2 | Jina-v3 | Nomic | E5-large |
|---|---|---|---|---|
| 段落（结构） | **0.4303** | **0.4948** | 0.4787 | **0.4997** |
| 句子（机械） | 0.4262 | 0.4723 | 0.4760 | 0.4828 |
| 定长 256 token（机械） | 0.4136 | 0.4849 | **0.4801** | 0.4863 |
| 语义（相邻句断点） | 0.4104 | 0.4726 | 0.4613 | 0.4810 |
| LumberChunker（LLM） | 0.4270 | 0.4690 | 0.4762 | 0.4830 |
| 命题（LLM） | 0.3484 | 0.3888 | 0.3937 | 0.3883 |

**差值（本文计算，pts）**

| | Jina-v2 | Jina-v3 | Nomic | E5-large |
|---|---|---|---|---|
| 段落 − 定长 | +1.67 | +0.99 | −0.14 | +1.34 |
| 段落 − 语义 | +1.99 | +2.22 | +1.74 | +1.87 |
| 定长 − 语义 | +0.32 | +1.23 | +1.88 | +0.53 |

**其他证据**：
- **语义切分**：四个模型下均低于段落和定长切分。它也是全文唯一没能稳定复现原论文结果的方法：FiQA 0.303 → 0.223，TREC-COVID 0.662 → 0.625。
- **命题切分**：比段落低 15–27%，在 ArguAna 上低 35–50%。
- **成本**：LumberChunker 每秒处理 1.11 篇文档，段落切分 1,854 篇，相差约 1,600 倍。
- **文档内检索（GutenQA，对照）**：结论反转，LumberChunker 四个模型全胜，比段落高 10–30%。
- **上下文化切分（late chunking）**：
  - 语料库内：命题法平均 +15.6% 到 +27.1%；段落约 ±0%，句子与定长 −0.6% 到 +7.2%；语义法在 FiQA 上反而 −23% 到 −27%。
  - 文档内：全面退化，Nomic 平均 −53.17%。

**结论**：语料库内检索用结构化方法即可。语义和 LLM 切分没有效果优势，成本却高出几个数量级。

## 2. Qu 等，NAACL Findings 2025

**设置**：
- 先用 spaCy 分句。机械切分为每 N 句一块，相邻块重叠 0–1 句。
- 每个数据集随机 100 条 query；检索前 k 块，映射回文档后计算 F1@5。
- 向量模型 Stella-1.5B。
- 10 个数据集中有 6 个是把短文档拼接成长文档（带 *）。

**表 1，文档检索 F1@5（%）**

| 数据集 | 机械 | 语义断点 | 语义聚类 | 机械 − 断点 |
|---|---|---|---|---|
| Miracl* | 69.45 | **81.89** | 67.35 | −12.44 |
| NQ* | 43.79 | **63.93** | 41.01 | −20.14 |
| Scidocs* | 16.82 | 17.60 | **19.87** | −0.78 |
| Scifact* | 35.27 | **36.27** | 35.70 | −1.00 |
| BioASQ* | 61.86 | 61.87 | **62.49** | −0.01 |
| NFCorpus* | 21.36 | 21.07 | **22.12** | +0.29 |
| HotpotQA | **90.59** | 87.37 | 84.79 | +3.22 |
| MSMARCO（网页） | **93.58** | 92.23 | 93.18 | +1.35 |
| ConditionalQA | **68.11** | 64.44 | 65.94 | +3.67 |
| Qasper | **90.99** | 89.27 | 90.77 | +1.72 |

**其他任务**：
- 证据检索 F1@5：三者差距在 1.6 pts 以内。
- 答案生成 BERTScore：三者基本相同（如 ExpertQA 均为 0.65）。

**结论**：
- 在 4 个未拼接的真实数据集上，机械切分全部领先语义断点 1.35–3.67 pts。
- 语义切分的大胜只出现在人工拼接、主题混杂的文档上。作者的解释是，断点法把拼接前的原始文档边界找了回来。
- 这篇论文没有测试结构切分。

## 3. Chen 等，Dense X Retrieval，EMNLP 2024

**设置**：
- 语料：英文维基，按三种粒度建索引，分别为 4,139 万段落、1.14 亿句子、2.57 亿命题。
- 5 个问答集（NQ、TriviaQA、WebQ、SQuAD、EntityQuestions）。
- 指标：段落召回 Recall@5 / Recall@20。

**五个数据集的平均值**

| 检索器 | 段落 | 句子 | 命题 |
|---|---|---|---|
| SimCSE（无监督） | 34.3 / 49.1 | 40.9 / 56.8 | 46.3 / 61.7 |
| Contriever（无监督） | 43.0 / 62.8 | 47.3 / 66.1 | 52.7 / 70.5 |
| DPR（有监督） | 57.3 / 69.5 | 59.2 / 71.0 | 59.9 / 72.2 |
| GTR（有监督） | 65.2 / 76.6 | 66.7 / 78.4 | 68.0 / 79.2 |

**结论**：
- 在这套大规模维基语料上，更细的粒度对无监督检索器提升大（Recall@20 平均 +10.1），对有监督检索器提升小（+2.7）。
- 这与第 1 节"命题切分在 BEIR 上最差"相矛盾，说明粒度效应依赖语料和模型，不能直接外推。

## 4. Jimeno Yepes 等，Financial Report Chunking（arXiv 2402.05131）

**设置**：
- FinanceBench，80 份美国上市公司财报。
- 元素切分规则：遇到标题新起一块；表格整张单独成块，不拆分；不足 2,048 字符的元素与后续元素合并。

| 策略 | 块数 | 页面命中率 | ROUGE | BLEU | 问答准确率（GPT-4 评） | 问答准确率（人工评） |
|---|---|---|---|---|---|---|
| 定长 128 token | 64,058 | 72.34 | 0.383 | 0.181 | 29.08 | 35.46 |
| 定长 256 token | 32,051 | **73.05** | 0.433 | 0.231 | 32.62 | 36.88 |
| 定长 512 token | 16,046 | 68.09 | 0.455 | 0.250 | 41.84 | 48.23 |
| 元素切分 + 关键词 | 20,843 | 46.10 | 0.444 | 0.315 | **43.97** | **53.19** |
| 元素切分 + 摘要 | 20,843 | 62.41 | 0.473 | 0.350 | **43.97** | 51.77 |
| 元素切分 + 前缀 / 表格说明 | 20,843 | 67.38 | **0.514** | **0.400** | 41.13 | **53.19** |

**结论**：
- 结构元素切分的块数比定长 256 少 35%，人工评问答准确率比最好的定长方案（512）高 4.96 pts，段落级指标也更高。
- 但页面命中率低于定长 256（67.38 对 73.05）。
- 即文档级命中不占优，内容层面占优。

## 5. NVIDIA 技术博客，2025-06

**设置**：
- 5 个 PDF 数据集（DigitalCorpora767、Earnings、FinanceBench、KG-RAG、RAGBattlePacket）。
- 向量检索加重排，取前 10；llama-3.1-nemotron-70b 生成答案；以端到端答案准确率评测（RAGAS，0–4 分）。
- 表格和图表整体保留，不参与切分。

| 策略 | 平均答案准确率 | 标准差 |
|---|---|---|
| 页级切分 | **0.648** | **0.107**（最稳定） |
| 定长 token（128–2,048） | 0.603–0.645 | — |
| 章节级切分 | 低于页级（仅在 FinanceBench 上胜出） | — |

**结论**：
- 按文档自然单元（页）切，平均效果最好且最稳定。
- 中等块长（256–1,024 token）普遍优于过小（128）和过大（2,048）。
- 重叠只在单个数据集上做了 10/15/20% 的比较，15% 最好，不是完整的参数搜索。

## 6. Chroma 技术报告，2024

**设置**：
- 5 个语料，共约 33 万 token、472 条 query；在每个语料内检索前 5 块。
- 指标为 token 级：召回 = 相关 token 被检索到的比例；IoU 会惩罚冗余内容。
- 向量模型 text-embedding-3-large。

| 方法 | 块长（平均 token） | 重叠 | 召回 | 精确率 | IoU |
|---|---|---|---|---|---|
| 递归 800（OpenAI 默认量级） | ~661 | 400 | 85.4 | 1.5 | 1.5 |
| 递归 400 | ~312 | 200 | 88.1 | 3.3 | 3.3 |
| 递归 400 | ~276 | 0 | 89.5 | 3.6 | 3.6 |
| 递归 200 | ~137 | 0 | 88.1 | 7.0 | 6.9 |
| 语义断点（Kamradt） | ~660 | 0 | 83.6 | 1.5 | 1.5 |
| 语义聚类 400 | ~182 | 0 | 91.3 | 4.5 | 4.5 |
| 语义聚类 200 | ~103 | 0 | 87.3 | **8.0** | **8.0** |
| LLM（GPT-4o） | ~240 | 0 | **91.9** | 3.9 | 3.9 |

**结论**：
- 默认参数的语义断点法召回最低（83.6）。
- 带长度约束的语义聚类和 LLM 切分召回较高，但需要额外计算。
- 块长 400 时，重叠 200 不提升召回（88.1 对 89.5），还会降低 IoU。

## 8. 跨论文规律

| 对比 | 证据 | 规律 |
|---|---|---|
| 机械 vs 语义 | Qu：真实数据集上机械领先 1.35–3.67 pts；Zhou：四个模型下语义均低于定长（0.32–1.88 pts）；Chroma：默认语义断点召回最低 | 真实语料上，向量断点式语义切分不优于机械切分，成本更高 |
| 结构 vs 语义 | Zhou：段落比语义高 1.74–2.22 pts；P09：结构 MRR 0.644 对语义 0.557 | 语料库内检索中结构切分更好 |
| 结构 vs 机械 | Zhou：段落比定长高 −0.14 到 +1.67 pts；Jimeno Yepes：问答 +4.96 pts，页面命中 −5.67 pts；NVIDIA：页级最好且最稳定 | 文档级排序提升小（约 1–3% 以内），内容层面（问答、证据）提升更明显 |
| 块长与粒度 | Dense X、Bhat、NVIDIA、Chroma | 影响明显且随语料、模型变化；比较时必须控制块长或字数预算 |
| 重叠 | Chroma、P08 无收益；NVIDIA 单数据集 15% 最好 | 没有稳定收益，增加索引成本 |
| 上下文化向量 | Zhou 表 4 | 对小块（命题）帮助大，对段落约 ±0%，对句子与定长 −0.6% 到 +7.2%；在文档内检索上有害 |

## 9. 与我们结果的对照

| 文献规律 | 我们的结果 |
|---|---|
| 文档级排序对切分不敏感（Zhou：结构化方法彼此差 1–3%；MaxP 聚合吸收了块边界差异） | 网页 recall@10：md_struct 0.1433、content_br 0.1463，基本持平 |
| 结构切分优于机械切分，幅度在几个百分点 | md_struct Δhit@3000字 +2.9 [+1.7, +4.1]；html 有内容时 html_struct 比 content_br 高 +2.1 到 +2.7 |
| 结构收益主要在内容层面，集中在有结构的文档（Jimeno Yepes：表格整块、问答提升） | html_struct 对 md_struct：表格网页 +2.1 / +1.8，纯文本 +0.6 / +1.4（3000 字召回 / 前 10 网页召回） |
| 块长是重要混杂因素 | md_struct 块长 170 字、content_br 229 字；html_struct 与 md_struct 块长接近，二者对比基本排除了块长影响 |

## 10. 证据边界

1. **没有一篇测过 HTML / DOM 结构切分**。Zhou 的"段落"是按换行切，Jimeno Yepes 是 PDF 版面元素，NVIDIA 是 PDF 页。我们的实验（346 万中文网页、HTML 结构）在文献中没有直接先例。
2. **语料规模**：除 Dense X（英文维基）外，各实验语料都在几百到几万篇文档量级，远小于我们。
3. **语言与领域**：全部是英文；没有中文网页。
4. **指标口径不一**：F1@5、nDCG@10、Recall@k、token 级 IoU、端到端准确率各不相同，跨论文只能比较方向，不能直接比较数值。
